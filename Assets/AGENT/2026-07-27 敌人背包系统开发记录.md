# 2026-07-27 敌人背包系统开发记录

## 1. 本次开发目标

在现有玩家背包和战斗系统基础上，新增正式的只读敌人背包，并接入 `SampleScene`。

本次完成的主要内容：

- 新增敌人背包专用数据资产。
- 新增只读敌人背包运行时系统。
- 支持准备阶段多次、原子地替换敌人背包数据。
- 创建与玩家背包上下镜像的敌人 UI。
- 为敌人背包提供独立的碰撞中心和飞机生成锚点。
- 让玩家和敌人同时播放准备阶段退出动效。
- 将玩家调试窗口扩展为统一的 Backpack Debug。
- 修复敌人 UI 中重复出现背包面板的问题。
- 将敌机飞行改为在曲线范围内随机选取路线。
- 补充敌人背包 EditMode 测试。

第一版仍然遵循以下约束：

- 场景中只有一个活动玩家背包和一个活动敌人背包。
- 敌人背包固定为 `7 × 4`。
- 敌人背包不能拖放或点击。
- 敌人数据只能在准备阶段更新。
- 数据更新为同帧原子刷新，不播放逐件放置动画。

## 3. EnemyBackpackData

脚本：

```text
Assets/Scripts/BackpackPrototype/EnemyBackpackData.cs
```

`EnemyBackpackData` 是敌人背包的 `ScriptableObject` 数据类型。

每个 `BackpackLayoutEntry` 包含：

```csharp
ItemData ItemData
Vector2Int AnchorCell
```

数据资产只保存固定布局，不改变背包尺寸。

默认数据资产：

```text
Assets/Data/Backpack/EnemyBackpacks/EnemyBackpack_Default.asset
```

默认布局与玩家当前默认布局一致：

```text
Aircraft_First  -> (1, 1)
Equipment_First -> (1, 0)
```

## 4. EnemyBackpackSystem

脚本：

```text
Assets/Scripts/BackpackPrototype/EnemyBackpackSystem.cs
```

这是敌人背包的正式运行时入口，负责连接：

- `BackpackCombatController`
- `BackpackFighterSpawner`
- `BackpackGridView`
- 物品显示层
- 物品 Prefab Catalog
- `CollisionCenterAnchor`
- `AircraftSpawnAnchor`

### 4.1 公开接口

```csharp
EnemyBackpackData DefaultData
EnemyBackpackData CurrentData
IReadOnlyList<ItemInstance> Items
bool IsReady

bool ApplyData(EnemyBackpackData data)
bool RestoreDefaultData()
```

### 4.2 数据应用规则

`ApplyData(...)` 只允许在 `Preparation` 阶段执行。

应用数据之前会使用临时 `BackpackController` 验证全部条目：

- 数据资产不能为空。
- 布局条目不能为空。
- `ItemData` 必须存在。
- 对应物品 Prefab 必须存在于 Catalog。
- 物品不能越过 `7 × 4` 边界。
- 多格物品之间不能重叠。

只有全部验证成功后才会：

1. 清空待生成飞机队列。
2. 清空旧布局。
3. 提交完整的新布局。
4. 更新 `CurrentData`。
5. 重建敌人只读物品视觉。

任何验证失败都会返回 `false`，原数据、布局和视觉保持不变。

重复应用同一个数据资产也会执行完整重载。

### 4.3 只读交互

敌人 `ItemView` 永久关闭交互，不参与：

- 点击
- 拖动
- 放置预览
- 垃圾区检测
- 商店逻辑

## 5. 敌人 UI 与镜像规则

敌人 UI：

```text
Assets/Prefabs/BackpackUI/EnemyBackpackUIAnimated.prefab
```

它复用玩家的：

- 背包背景
- `7 × 4` 网格
- 物品尺寸
- UI 材质
- Show/Hide 动效时长、缓动和缩放曲线

敌人 UI 不显示：

- 商店
- Roll
- Ready
- 垃圾区
- 战斗阶段文字

镜像规则：

- 玩家背包位于屏幕下方。
- 敌人背包位于屏幕上方。
- Show/Hide 位移动效在 Y 方向镜像。
- 敌方图标、文字和格子内容保持正向，不整体倒置。
- 格子 `(0, 0)` 对双方都仍然是左上角。

### 5.1 动画阶段推进权

`PreparationActionsPhaseMotion` 新增：

```csharp
bool completesCombatTransition
```

配置规则：

- 玩家：`true`
- 敌人：`false`

双方会同时播放 Hide 动画，但只有玩家动画完成回调可以把：

```text
CombatTransition -> Combat
```

敌人动画不会重复推进战斗阶段。

## 6. 位置调整方式

玩家和敌人的位置不是运行时实时绑定。

敌人 UI 是在编辑器生成阶段，根据玩家 UI 复制并镜像得到的。

推荐调整流程：

1. 打开 `PlayerBackpackUIAnimated.prefab`。
2. 调整 `PlayerBackpackScaleRoot` 的 `RectTransform.AnchoredPosition`。
3. 主要修改 Y 坐标。
4. 执行：

```text
Tools > Backpack > Build Complete Enemy Backpack
```

5. 生成器会重新创建敌人 UI，并对关键 Y 坐标和动效位置取反。

例如：

```text
玩家 Y = -483
敌人 Y =  483
```

不要通过移动顶层 `PlayerBackpackSystem` 来调整 UI，因为顶层对象还包含战斗组件和世界表现。

不要只移动内部网格。优先移动 `PlayerBackpackScaleRoot`，让背景、网格、物品和相关锚点保持一致。

### 6.1 在 SampleScene 中直接移动

如果直接在 `SampleScene` 中移动玩家 UI：

- 只会创建该场景的 Prefab Override。
- 敌人不会自动镜像移动。
- 敌人生成脚本不会读取这个场景 Override。
- MMFeedbacks 使用保存的位置值，动画时可能跳回原位置。

场景内移动适合临时试位置。

确认位置后，应将修改 Apply 到玩家 UI Prefab，再重新构建敌人背包。

如果直接修改 `EnemyBackpackScaleRoot`，可以让敌人使用独立位置；但以后再次运行完整敌人背包构建时，该位置会被重新生成。

## 7. 世界锚点

玩家和敌人现在都使用自己的 UI 锚点投影到世界坐标，不再通过玩家坐标推算虚拟敌方位置。

### 7.1 CollisionCenterAnchor

用途：

- 表示 UI 背包在战斗世界中的中心。
- 用于放置世界背包、碰撞目标和相关战斗表现。

### 7.2 AircraftSpawnAnchor

用途：

- 表示飞机生成位置。
- 玩家生成点位于玩家背包上方。
- 敌人生成点位于敌人背包下方。

敌人世界背包中心、血条和飞机生成点因此可以独立跟随敌人 UI。

## 8. 重复敌人背包问题

施工后曾出现 `SampleScene` 中看起来存在多个敌人背包的问题。

检查结果：

- `SampleScene` 实际只有一个 `EnemyBackpack` Prefab 实例。
- 重复视觉来自 `EnemyBackpackUIAnimated.prefab` 内部。
- 克隆玩家 UI 时遗留了一个同级 `PlayerBackpack (1)`。

修复后敌人 UI 只包含：

```text
1 × EnemyBackpack
1 × BackpackGridView
```

`EnemyBackpackSystemMigration` 已增加重复面板清理逻辑，重新构建时不会再次保留同级的 `PlayerBackpack (1)`。

测试中也增加了“敌人 Prefab 只能包含一个 BackpackGridView”的断言。

## 9. 敌机随机曲线

脚本：

```text
Assets/Scripts/BackpackPrototype/BackpackFighterSpawner.cs
```

原敌人背包生成器使用：

```text
curveValue = 0
```

因此敌机基本沿中线垂直向下飞行。

现在的规则：

- 玩家飞机继续使用玩家当前的滑动曲线值。
- 每架敌机进入生成队列时，独立随机采样一次曲线值。
- 默认敌人曲线范围为 `[-1, 1]`。
- 已排队飞机保存采样结果，不会受后续配置变化影响。
- 显式传入曲线值时可以覆盖随机值，便于调试和特殊敌人逻辑。

新增配置：

```csharp
Vector2 EnemyCurveValueRange
void SetEnemyCurveValueRange(Vector2 range)
float SampleEnemyCurveValue()
```

范围会：

- 自动按从小到大排序。
- 限制在 `[-1, 1]`。

例如：

```text
[-1.0, 1.0]  曲线覆盖完整范围
[-0.5, 0.5]  敌机更集中于中间
[ 0.3, 0.8]  敌机偏向曲线的一侧
```

敌机的基础朝向仍然是 `Vector2.down`，但 `BattleCurveFollower2D` 会立即根据本次随机曲线设置实际飞行方向。

## 10. 统一 Backpack Debug

正式菜单：

```text
Tools > Backpack > Backpack Debug
```

兼容入口：

```text
Tools > Backpack > Player Backpack Debug
```

调试窗口提供目标选择：

```text
Player [Player]
Enemy [Enemy]
```

双方都可以查看：

- 当前阶段
- 背包尺寸
- 物品数量
- 布局坐标
- 冷却状态
- 飞机生成队列
- 相邻装备增益

玩家额外保留：

- 商店刷新
- 恢复默认布局
- 曲线值
- 冷却操作

敌人额外提供：

- `CurrentData`
- `EnemyBackpackData` 选择框
- 应用数据
- 恢复默认数据

敌人数据应用按钮只在准备阶段可用。

原 Battle Debug 保持独立，没有复制敌人背包数据操作。

## 14. 当前维护原则

- 敌人背包数据变化应通过 `EnemyBackpackData` 和 `ApplyData(...)` 完成。
- 不要直接修改运行时 `BackpackController` 来绕过原子验证。
- 敌人物品视觉必须保持只读。
- 调整对称 UI 时，以玩家 Prefab 为源并重新运行敌人构建工具。
- 独立调整敌人位置时，需要注意重新构建会覆盖生成资源。
- 玩家曲线由输入控制，敌人曲线由生成器逐架随机采样。
- `SampleScene` 中应始终只有一个活动敌人背包实例。
