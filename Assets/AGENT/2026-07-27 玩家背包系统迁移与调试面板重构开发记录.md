# 2026-07-27 玩家背包系统迁移与调试面板重构开发记录

## 1. 本次开发目标

将 `BackpackDebugScene` 中已经验证过的玩家背包能力迁移为可直接接入正式场景的完整预制体，并接入 `SampleScene`。

本次处理的主要内容：

- 统一背包 UI、商店、拖放、丢弃、战斗冷却与飞机生成入口。
- 让 UI 和战斗逻辑共享同一个 `BackpackController`。
- 接入横向滑动曲线输入。
- 建立相邻装备 Buff 扩展协议。
- 将背包调试工具重构为 Runtime 桥加 EditorWindow。
- 恢复原 `BackpackDebugScene` 中的 MMFeedbacks 阶段动效。
- 删除迁移完成后的 `BackpackDebugScene`，保留其他调试脚本与编辑器工具。

本轮明确不实现：

- 金币、价格和购买失败规则。
- 磁盘存档及布局恢复。
- 未定义的伤害、速度、生命等装备数值。

商店仍然是三个槽位的免费随机获取。

## 5. PlayerBackpackSystem

脚本：

```text
Assets/Scripts/BackpackPrototype/PlayerBackpackSystem.cs
```

这是玩家背包的正式运行时入口，负责连接：

- `BackpackCombatController`
- `BackpackFighterSpawner`
- `BackpackGridView`
- 背包和商店中的 `ItemView`
- 垃圾区
- 曲线输入
- 准备/战斗阶段

### 5.1 数据唯一来源

UI 不再创建第二份背包数据。

```text
PlayerBackpackSystem
        │
        ▼
BackpackCombatController.Backpack
        │
        ▼
BackpackController
```

拖放、布局读取、冷却和邻接检测都使用同一个 `BackpackController`。

### 5.2 公开接口

```csharp
BackpackController Backpack
IReadOnlyList<ItemInstance> Items

bool LoadLayout(IReadOnlyList<BackpackLayoutItem> layout)
void RestoreDefaultLayout()
void RefreshShop()
void EnterCombat()

void BindCurveInput(HorizontalSwipeCurveInput input)
void SetFlightCurveValue(float value)
```

### 5.3 布局加载规则

`LoadLayout(...)` 只允许在准备阶段调用。

加载过程先使用临时 `BackpackController` 完整验证：

- 物品配置是否存在。
- UI Prefab 是否在 Catalog 中注册。
- 锚点是否越界。
- 多格物品是否重叠。

全部条目通过后才清空并提交正式布局。任何条目失败时，原布局保持不变，避免模型和 UI 只更新一半。

### 5.4 商店

- 进入准备阶段后的首次启动自动填充商店。
- 三个槽位分别随机抽取。
- 允许出现重复商品。
- `Roll` 调用 `PlayerBackpackSystem.RefreshShop()`。
- 本轮所有商品免费。

### 5.5 阶段行为

准备阶段：

- 允许商店拖入。
- 允许背包内移动。
- 允许垃圾区删除。
- 重置所有飞机物品冷却。
- 清理飞机生成队列。
- 播放准备模块进入动效。

战斗阶段：

- 禁止商店和背包拖放。
- 所有飞机物品开始冷却。
- 冷却完成后进入飞机生成队列。
- 播放准备模块退出动效。
- 开启横向滑动曲线输入。

## 6. 飞行曲线输入

`SampleScene` 中的 `HorizontalSwipeCurveInput` 已绑定到玩家 `PlayerBackpackSystem`。

规则：

- 输入值限制在 `[-1, 1]`。
- 准备阶段关闭曲线手势。
- 战斗阶段启用曲线手势。
- 曲线显示和背包飞机生成器读取同一个输入源。
- 飞机在冷却完成并进入生成队列时截取曲线值。
- 已排队或已经生成的飞机不会被后续输入修改。
- 未绑定输入时使用 `0`，即垂直直线，并只输出一次配置警告。

`HorizontalSwipeCurveDebugRuntime` 不再在正式玩家背包存在时抢占输入启用权。

## 7. 相邻装备 Buff

新增协议：

```text
Assets/Scripts/BackpackPrototype/IAircraftEquipmentBuff.cs
```

接口：

```csharp
void Apply(Fighter2D fighter, ItemInstance sourceItem);
```

飞机生成时：

1. 读取飞机物品四方向相邻装备。
2. 每个相邻装备实例独立处理。
3. 实例化装备配置的效果 Prefab。
4. 查找效果 Prefab 子层级中的所有 `IAircraftEquipmentBuff`。
5. 将生成后的 `Fighter2D` 和来源 `ItemInstance` 传入。

本次取消了按效果 Prefab 去重的旧行为。

因此，即使两个独立装备使用相同效果 Prefab，它们也会分别实例化并分别调用 Buff，给未来叠加规则保留空间。

当前橙色粒子仍是首个表现效果。没有擅自添加伤害、速度或生命数值。

## 8. 飞机生成链路

正式玩家飞机只通过以下链路生成：

```text
战斗阶段
  ↓
ItemInstance推进冷却
  ↓
BackpackCombatController.CooldownCompleted
  ↓
BackpackFighterSpawner.RequestSpawn
  ↓
生成队列截取当前曲线
  ↓
生成并初始化Fighter2D
  ↓
应用全部相邻装备效果和Buff
```

`SampleScene` 中会形成第二套生成入口的 `BattleDebugRuntime` 已移除。

生成器仍保留：

- 阵营颜色。
- 玩家向上、敌方向下的默认方向。
- 生成间隔。
- 最近敌方背包查找。
- 曲线跟随器初始化。
- 返回准备阶段时清空队列。

## 10. 原有阶段动效恢复

迁移后曾出现准备模块动效消失。

原因不是调试窗口重构，而是旧动效原本只存在于 `BackpackDebugScene` 的场景 Override：

- `PreparationActionsMotionController`
- `ShowFeedbacks`
- `HideFeedbacks`
- `MMF_Position`
- `MMF_Scale`
- Hide 完成后关闭模块的回调

这些对象不在原 `BackpackDebugUI.prefab` 中，因此第一次正式预制体组装没有携带它们。

修复方式：

- 从旧场景历史版本提取原始 MMFeedbacks 配置。
- 将控制器和目标 UI 放入同一个 Prefab，保留内部引用。
- 生成：

```text
Assets/Prefabs/BackpackUI/PlayerBackpackUIAnimated.prefab
```

- 正式 `PlayerBackpackSystem.prefab` 改为嵌套该动画 UI。

没有重新设计或修改原动效参数。

恢复的表现包括：

- 准备模块进入位置动画。
- Ready 按钮缩放动画。
- 玩家背包 UI 位置动画。
- 进入战斗时的退出动画。
- Hide 完成后关闭准备模块。

物品 Hover、Punch、Shake 和冷却闪光仍继续使用原 DOTween 代码。

## 16. 当前边界与后续建议

- 商店无金币和价格。
