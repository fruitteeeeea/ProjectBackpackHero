# 子弹系统与发射系统设计文档

日期：2026-07-28

适用场景：`SampleScene`、`BattlePrototype`

命名空间：`BackpackHero.Battle`

## 1. 系统目标

本系统把“子弹如何运动和命中”与“一个单位何时、朝哪些方向发射”拆成两个独立层级。

```text
飞机 / TestShooter
        │
        │ 提供当前正前方和发射时机
        ▼
ProjectileFireModeController2D
        │
        │ Pattern生成一个或多个方向
        ▼
Projectile2D实例
        ├── DirectionalMover2D：移动和朝向
        ├── HitBox2D：阵营和伤害
        └── LifetimeAndScreenBounds2D：生命周期
```

拆分后的组合关系：

- 同一个子弹 Prefab 可以配合单发、散射等不同发射模式。
- 同一个发射模式可以发射普通弹、追踪弹、爆炸弹等不同 Prefab。
- 一个飞机可以同时拥有多个发射模式，每个模式独立冷却。
- TestShooter 可以在 Play Mode 中动态增删模式，用于验证后续子弹设计。

## 3. 子弹系统

### 3.1 Projectile2D

`Projectile2D` 是一颗子弹的统一初始化入口，不直接负责逐帧移动或碰撞伤害。

```csharp
Initialize(
    BattleFaction faction,
    float damage,
    float speed,
    Vector2 direction)

Initialize(
    BattleFaction faction,
    float damage,
    float speed,
    Vector2 direction,
    ProjectileTrajectoryLaunchContext context)
```

初始化流程：

1. 把阵营和伤害交给 `HitBox2D`。
2. 把速度和发射快照交给 `ProjectileTrajectoryController2D`。
3. 轨迹控制器从 Profile 创建本颗子弹独立的 Runtime。
4. Runtime 按累计路程计算位置和切线，切线同时更新 `transform.up`。
5. 零方向依次回退到子弹当前朝向和 `Vector2.up`。

四参数重载继续保留，用于没有目标的旧调用。它会以子弹生成位置和当前方向构造无目标上下文。

### 3.2 ProjectileTrajectoryController2D

轨迹控制器挂在子弹 Prefab 根对象上，并引用一个 `ProjectileTrajectoryProfile` ScriptableObject。

`ProjectileTrajectoryLaunchContext` 在发射瞬间保存：

- 子弹生成位置和 Pattern 产生的实际发射方向。
- 发射者位置和朝向。
- 是否存在目标以及目标中心点世界坐标。

上下文不保存目标 Transform，因此敌人之后移动或销毁都不会改变已经生成的轨迹。

控制器以 `ProjectileSpeed * deltaTime` 累加实际路径距离，再向本颗子弹的 Runtime 查询位置和切线。Profile 只保存可复用配置，不保存运行时进度。

异常回退规则：

- 未配置 Profile。
- 贝塞尔轨迹没有目标。
- 目标与起点重合导致曲线退化。

以上情况只警告一次并回退为直线，子弹不会停在原地。

### 3.3 当前轨迹 Profile

| 资源 | 行为 | 默认参数 |
|---|---|---|
| `Straight.asset` | 沿 Pattern 发射方向匀速直飞 | 无额外参数 |
| `Sine.asset` | 以 Pattern 发射方向为中轴持续 S 形运动 | 振幅 `0.25`、波长 `1.5`、每周期 `64` 采样 |
| `BezierRandom.asset` | 起点 → 发射者左/右后方控制点 → 目标快照 | 后退 `0.5`、侧向 `0.75`、`32` 采样、随机侧 |

S 形对一个周期进行弧长采样，之后循环映射累计路程。因此弯曲段不会因为直接按参数推进而明显加速。

贝塞尔使用二次贝塞尔曲线并预采样累计弧长。侧向支持：

```text
Left
Right
Random
```

`Random` 在每颗子弹初始化时只选择一次。子弹走完曲线但没有命中时，会沿曲线末端切线继续直飞，最后仍由寿命或出屏组件销毁。

### 3.4 DirectionalMover2D

职责：

- 保存世界空间标准化方向。
- 根据基础速度和速度倍率进行直线移动。
- 方向改变时同步视觉朝向。
- 支持暂停和恢复。

`DirectionalMover2D` 继续服务飞机和普通直线移动对象，不负责子弹轨迹。飞机和子弹素材仍统一约定本地 Y 轴正方向为“前方”。

### 3.5 HitBox2D

职责：

- 保存本次子弹的阵营和伤害。
- 根据阵营设置 Player/Enemy HitBox Layer。
- 只对敌方、存活的 `HurtBox2D` 造成伤害。
- 一颗子弹有效命中一次后立即销毁。
- 友军碰撞不会造成伤害，也不会消耗子弹。

物理 Layer 和 `HurtBox2D.ReceiveHit()` 的阵营检查共同构成双层保护。

### 3.6 LifetimeAndScreenBounds2D

职责：

- 到达生命周期后销毁。
- 进入过屏幕后，离开屏幕边界时销毁。
- `SetLifetime()` 允许 TestShooter 在生成子弹后覆盖 Prefab 默认寿命。

该组件对 `Projectile2D` 不是强制依赖。缺失时子弹仍可发射，但调试面板中的寿命设置不会生效。

## 4. 发射系统

### 4.1 ProjectileFirePattern

`ProjectileFirePattern` 是 ScriptableObject 数据基类，只负责把一个正前方转换成一组发射方向。

```csharp
public abstract void AppendDirections(
    Vector2 forward,
    List<Vector2> results);
```

Pattern 不负责：

- 冷却。
- 输入。
- 生成 GameObject。
- 伤害、速度或阵营。
- 寻找攻击目标。

因此 Pattern 可以在飞机、TestShooter 和后续武器系统中复用。

### 4.2 当前 Pattern 数据

| 数据资源 | 类型 | 行为 |
|---|---|---|
| `ForwardSingle.asset` | `ForwardProjectileFirePattern` | 朝当前正前方发射 1 颗 |
| `Spread30Three.asset` | `SpreadProjectileFirePattern` | 在完整 30° 扇形内均匀发射 3 颗 |

三发散射的相对角度为：

```text
-15°       0°       +15°
   ↖        ↑        ↗
```

散射计算规则：

```text
step = spreadAngle / (projectileCount - 1)
start = -spreadAngle / 2
angle(index) = start + step * index
```

当数量为 1 时直接返回正前方，避免除以零。

### 4.3 ProjectileFireMode

一个发射模式由以下运行时数据组成：

```text
ProjectileFirePattern Pattern
float Interval
float RemainingCooldown
```

间隔规则：

- `Interval < 0`：统一归一为 `-1`，表示手动模式。
- `Interval >= 0`：最小自动间隔为 `0.02s`。
- 每个模式拥有自己的 `RemainingCooldown`，互不共享。
- 重设模式间隔时，该模式冷却立即重置。

### 4.4 ProjectileFireModeController2D

这是飞机与 TestShooter 共用的发射模块。

主要接口：

```csharp
Tick(deltaTime, forward)
TriggerAll(forward)
AddMode(pattern, interval)
RemoveModeAt(index)
SetModePattern(index, pattern)
SetModeInterval(index, interval)
ReplaceWithSingleMode(pattern, interval)
ResetCooldowns()
```

控制器不直接实例化子弹，而是针对 Pattern 生成的每个方向发送：

```csharp
event Action<Vector2> ShotRequested;
```

使用方订阅该事件，然后决定：

- 使用哪个 Projectile Prefab。
- 从哪个 FirePoint 生成。
- 注入什么阵营、伤害、速度和寿命。

这种设计避免发射模块依赖飞机或 TestShooter 的业务数据。

## 5. 飞机接入

`Fighter.prefab` 包含一个 `ProjectileFireModeController2D`。

飞机初始化时：

1. `Fighter2D.Initialize()` 接收对应 `FighterDefinition`。
2. 调用 `FighterCombat2D.ConfigureDefaultFireMode()`。
3. 清空 Prefab 中的临时模式列表。
4. 添加 `ForwardSingle`。
5. 使用当前飞机自己的 `FighterDefinition.AttackInterval` 作为间隔。

当前间隔保持原有数值：

| 飞机 | 发射间隔 |
|---|---:|
| Normal Fighter | 0.5 秒 |
| Charge Fighter | 0.25 秒 |
| Shield Fighter | 1 秒 |

飞机发现目标并进入战斗后：

1. 暂停原移动和曲线跟随。
2. 转向目标。
3. `FighterCombat2D` 调用控制器的 `Tick()`。
4. 每个完成冷却的模式独立发送发射请求。
5. `FighterCombat2D` 从 FirePoint 生成并初始化子弹。

失去目标或退出战斗时，所有模式冷却重置。下次进入战斗会立即进行第一次发射。

后续装备需要给飞机增加模式时，应操作飞机身上的控制器：

```csharp
controller.AddMode(
    spreadPattern,
    0.75f);
```

移除、替换 Pattern 或改变间隔也必须调用控制器公开接口，不直接修改内部列表。

## 6. TestShooter 接入

`BattlePrototype/TestShooter` 的行为：

- 每帧朝向鼠标世界坐标。
- 鼠标与射手位置重合时保留上一有效朝向。
- 默认挂载一个 `ForwardSingle` 模式。
- TestShooter 上的所有模式间隔均为 `-1`。
- 单击鼠标左键时立即调用一次 `TriggerAllFireModes()`。
- 按住左键时按照 `ManualTriggerInterval` 重复主动触发，默认间隔为 `0.2s`。
- 一次主动触发会同时触发当前全部模式。
- 按住触发间隔属于 TestShooter 输入层；所有 Pattern 模式自身仍保持 `-1` 手动间隔。

例如 TestShooter 同时挂载：

```text
ForwardSingle
Spread30Three
```

单击一次会生成：

```text
1颗朝前子弹 + 3颗散射子弹 = 4颗
```

如果只需要三发散射，应先删除默认单发模式。

TestShooter 生成每颗子弹时统一注入调试面板当前设置的：

- Projectile Prefab。
- Faction。
- Damage。
- Speed。
- Lifetime。

## 7. Test Shooter Debug

菜单入口：

```text
Tools/Battle/Test Shooter Debug
```

生命周期：

- TestShooter Runtime 实例出现时自动打开。
- 实例销毁、场景切换或退出 Play Mode 时自动关闭。
- 重复注册或脚本重编译不会产生多个同类窗口。

面板功能：

- 查看连接对象、是否正在主动发射和当前朝向。
- 修改 Projectile Prefab、阵营、伤害、速度和寿命。
- 选择 Pattern 数据并添加手动发射模式。
- 修改已有模式的 Pattern。
- 删除已有模式。
- 设置 `Hold Trigger Interval`，控制左键按住时的重复触发速度。
- 点击“触发所有发射模式”进行测试。

面板只调用 `TestShooterDebugRuntimeBridge` 和公开业务接口，不直接修改运行时内部列表。

## 8. 制作新子弹 Prefab

基础子弹根对象至少需要：

```text
Projectile2D
ProjectileTrajectoryController2D
HitBox2D
FactionMember
Collider2D (Is Trigger)
Rigidbody2D
```

推荐同时添加：

```text
LifetimeAndScreenBounds2D
```

制作步骤：

1. 复制现有 `Projectile.prefab`。
2. 替换 Sprite、Collider 尺寸和表现组件。
3. 创建或复用一个 `ProjectileTrajectoryProfile`，并配置给轨迹控制器。
4. 保持素材前方为本地 Y 轴正方向。
5. 不在 Prefab 中写死最终阵营、伤害或速度；生成时由发射者注入。
6. 在 Test Shooter Debug 中选择新 Prefab。
7. 配合 `ForwardSingle` 和 `Spread30Three` 分别测试。

当前示例：

```text
Projectile.prefab          Straight
Projectile_Sine.prefab     Sine
Projectile_Bezier.prefab   BezierRandom
```

追踪、爆炸、穿透等行为应作为子弹 Prefab 上的独立组件实现，不应写入发射 Pattern：

```text
HomingProjectile2D
ExplosiveProjectile2D
PiercingProjectile2D
ChainProjectile2D
```

## 9. 制作新发射 Pattern

适合放在 Pattern 中的行为：

- 多方向散射。
- 环形发射。
- 固定角度侧射。
- 随机角度发射。

不适合放在 Pattern 中的行为：

- 子弹飞行中追踪。
- 命中后爆炸。
- 穿透次数。
- 伤害结算。

新 Pattern 的制作步骤：

1. 创建继承 `ProjectileFirePattern` 的 ScriptableObject 类。
2. 实现 `ProjectileCount`。
3. 在 `AppendDirections()` 中追加标准化方向。
4. 添加 `CreateAssetMenu`。
5. 在 `Assets/Settings/Battle/ProjectileFirePatterns` 创建数据资源。
6. 使用 TestShooter 调试面板添加并验证。

## 10. 当前测试覆盖

`TestShooter2DTests` 当前覆盖：

- 子弹调试参数边界。

## 12. BattleAttack与激光范围攻击扩展

发射系统现在可以生成统一的`BattleAttack2D`攻击实例：

```text
BattleAttack2D
├── Projectile2D
│   └── 轨迹移动 + HitBox单次碰撞
└── LaserBeamAttack2D
    └── SegmentBox范围查询 + 多目标伤害
```

每个`ProjectileFireMode`独立保存：

```text
BattleAttack2D AttackPrefab
ProjectileFirePattern Pattern
float Interval
```

`ShotRequested`发送`BattleShotRequest`，其中包含当前模式的攻击
Prefab、Pattern产生的实际方向和模式索引。同一个飞机或TestShooter
因此可以同时挂载普通子弹、激光和后续范围攻击。

所有攻击通过`BattleAttackLaunchContext`接收阵营、伤害、速度、寿命、
发射点、发射方向和AimPoint。AimPoint是瞄准参考点，不一定是每个
Pattern分支的最终终点。

激光长度取发射点到AimPoint的距离，终点按照Pattern方向计算：

```text
beamEnd = origin + patternDirection * aimDistance
```

所以`Spread30Three`会生成三束等长的`-15° / 0° / +15°`扇形激光，
而不是三束都连接同一个目标点。中心束仍准确连接目标或鼠标位置。

激光的默认时间线：

```text
0.0–0.1s  Alpha从0渐显到1
0.1s      对路径内所有敌方单位结算一次伤害
0.1–0.3s  保持完全显示
0.3–0.6s  Alpha从1渐隐到0
0.6s      销毁
```

范围攻击使用`AreaDamageResolver2D`和`DamageArea2D`。当前形状包括：

- `SegmentBoxDamageArea2D`：用于激光等线段矩形。
- `FixedBoxDamageArea2D`：用于后续火焰、毒雾等固定矩形区域。

范围查询仍复用敌方HurtBox Layer与`HurtBox2D.ReceiveHit()`的双层
阵营检查，并按`Health`去重，保证单束攻击不会因为一个单位拥有多个
HurtBox而重复扣血。不同攻击实例可以分别伤害同一个单位。
