# 2D 俯视角飞机与曲线飞行系统开发记录

## 1. 项目目标

在 Unity 中建立一个可扩展的 2D 俯视角飞机系统，当前包含：

- 飞机和子弹按照方向与自身速度飞行。
- 飞机生成时获得持续 0.5 秒的速度爆发。
- 爆发倍率通过 `AnimationCurve` 编辑，默认从 1.5 倍恢复至 1.0 倍。
- 飞机能够沿 Battle Curve 飞行。
- 飞离曲线后，沿曲线终点的最后方向继续直线飞行。
- 飞机默认存在 10 秒，进入屏幕后离开屏幕也会被销毁。
- 玩家飞机显示为淡蓝色，敌方飞机显示为淡红色。
- 玩家飞机从 `Player` 节点生成，默认方向向上。
- 敌方飞机从 `Enemy` 节点生成，默认方向向下。
- 玩家飞机采用生成瞬间的当前 Curve Line。
- 敌方飞机从指定曲线范围中随机选择曲线。
- 使用 EditorWindow 调试玩家和敌方飞机生成。
- 飞机机型数据与阵营、生成位置和飞行路径分离。
- 支持通过带权重的机型池随机生成不同飞机。

项目使用的 Unity 版本：

```text
Unity 6000.5.3f1
```

主要调试场景：

```text

```

原测试场景：

```text
Assets/Scenes/BattlePrototype.unity
```

在 `SampleScene` 完整验证通过以前，不建议立即删除原测试场景。

所有飞机和子弹素材默认方向均为朝上，因此运行时统一使用：

```csharp
transform.up = direction;
```

表示视觉朝向与飞行方向一致。

### Sprite 导入要求

每张飞机和子弹图片建议设置为：

```text
Texture Type       Sprite (2D and UI)
Sprite Mode        Multiple
Pixels Per Unit    100
Mesh Type          Full Rect
Filter Mode        Point (no filter)
Compression        None
Pivot              Center
```

需要特别确认 Sprite Editor 中每个切片的 Pivot 是中心 `(0.5, 0.5)`，否则旋转时会绕素材左下角旋转。

## 4. 系统架构

### 4.1 配置数据

`FighterDefinition` 是 ScriptableObject，只保存飞机不会随单个实例变化的静态配置：

```text
FighterDefinition
├── Display Name
├── Sprite
├── Base Color
├── Base Speed
└── Maximum Health
```

### 4.2 飞机运行时实例

`Fighter2D` 保存单架飞机的运行时状态：

```text
Fighter2D
├── 当前使用的 FighterDefinition
├── Current Health
└── Alive 状态
```

最大生命值可以来自 ScriptableObject，但当前生命值必须存在飞机实例中。

错误做法：

```csharp
definition.CurrentHealth -= damage;
```

因为多架飞机可能共享同一个 ScriptableObject，这会造成所有飞机共享血量。

正确关系：

```text
FighterDefinition
└── Maximum Health = 10

Fighter A
└── Current Health = 4

Fighter B
└── Current Health = 10
```

### 4.3 移动与轨迹

```text
DirectionalMover2D
├── 基础速度
├── 速度倍率
├── 当前方向
└── 直线移动

FighterFlight2D
└── 控制生成时的速度爆发曲线

BattleCurveFollower2D
├── 曲线采样
├── 按实际距离沿曲线移动
└── 曲线结束后恢复直线移动
```

最终速度：

```text
Current Speed = Base Speed × Speed Multiplier
```

### 4.4 生成与阵营

机型与阵营必须分离：

```text
FighterDefinition
└── 决定飞机是什么

Spawner / BattleDebugRuntime
├── 决定生成位置
├── 决定玩家或敌人阵营
├── 决定阵营颜色
├── 决定曲线
└── 决定使用哪一种机型
```

同一个冲锋战斗机配置既可以生成：

```text
淡蓝色玩家冲锋机
淡红色敌方冲锋机
```

不需要为双方创建两份机型数据。

## 5. 通用方向移动

脚本：

```text
Assets/Scripts/Battle/DirectionalMover2D.cs
```

核心字段：

```csharp
[SerializeField, Min(0f)]
private float baseSpeed = 5f;

[SerializeField, Min(0f)]
private float speedMultiplier = 1f;

[SerializeField]
private Vector2 direction = Vector2.up;
```

核心属性：

```csharp
public float BaseSpeed => baseSpeed;
public float SpeedMultiplier => speedMultiplier;
public float CurrentSpeed => baseSpeed * speedMultiplier;
public Vector2 Direction => direction;
```

设置方向：

```csharp
public void SetDirection(Vector2 newDirection)
{
    if (newDirection.sqrMagnitude <= Mathf.Epsilon)
    {
        return;
    }

    direction = newDirection.normalized;
    transform.up = direction;
}
```

移动公式：

```csharp
Vector2 movement =
    direction * CurrentSpeed * Time.deltaTime;

transform.position += (Vector3)movement;
```

使用标准化方向可以避免斜向飞行比水平、垂直飞行更快。

## 6. 飞机初始速度爆发

脚本：

```text
Assets/Scripts/Battle/Fighter/FighterFlight2D.cs
```

默认设置：

```text
Burst Duration     0.5 秒
曲线起点倍率        1.5
曲线终点倍率        1.0
```

曲线横轴使用归一化时间：

```text
0.0 = 爆发开始
0.5 = 经过 0.25 秒
1.0 = 经过 0.5 秒
```

每帧计算：

```csharp
float normalizedTime =
    Mathf.Clamp01(elapsedTime / burstDuration);

float multiplier =
    burstSpeedCurve.Evaluate(normalizedTime);

mover.SetSpeedMultiplier(multiplier);
```

推荐把关键点 Tangent 设置为 `Auto` 或 `Clamped Auto`，得到平滑的速度恢复过程。

## 7. Lifetime 与屏幕外销毁

脚本：

```text
Assets/Scripts/Battle/LifetimeAndScreenBounds2D.cs
```

飞机默认：

```text
Lifetime                    10
Destroy When Leaving Screen true
Viewport Margin             0.05
```

子弹可暂时设置：

```text
Lifetime                    5
Destroy When Leaving Screen true
Viewport Margin             0.05
```

屏幕判断使用：

```csharp
Camera.main.WorldToViewportPoint(transform.position);
```

不建议依赖 `OnBecameInvisible()`，因为编辑器的 Scene View 相机也可能影响它。

系统需要记录：

```csharp
private bool hasEnteredScreen;
```

这样从屏幕外生成、随后飞入屏幕的飞机不会被立即销毁。只有飞机曾进入屏幕，之后再次离开销毁边界时才销毁。

## 8. Battle Curve

当前 Curve Line 使用二次贝塞尔曲线。

脚本：

```text
Assets/Scripts/Battle/Curve/BattleCurve2D.cs
```

曲线由以下内容组成：

```text
Start
Control Point
End
```

曲线位置公式：

```csharp
return
    inverseT * inverseT * start +
    2f * inverseT * t * controlPoint +
    t * t * end;
```

切线公式：

```csharp
Vector3 tangent =
    2f * (1f - t) * (controlPoint - start) +
    2f * t * (end - controlPoint);
```

`CurvedConnectionRenderer` 和飞机跟随组件应共同调用 `BattleCurve2D`，避免显示曲线与实际飞行轨迹使用两套不同公式。

## 9. 曲线跟随

脚本：

```text
Assets/Scripts/Battle/Curve/BattleCurveFollower2D.cs
```

飞机生成时截取：

```text
起点位置
终点位置
Curve Value
Maximum Bend Distance
```

已经生成的飞机使用固定曲线快照。玩家继续调整 Curve Line 时，只影响之后生成的飞机。

跟随曲线期间：

```text
BattleCurveFollower2D 负责位置移动
DirectionalMover2D 暂时禁用
```

曲线结束时：

```text
1. 把飞机放到曲线终点
2. 计算最后一个采样段的方向
3. 设置 DirectionalMover2D 的方向
4. 恢复 DirectionalMover2D
5. 禁用 BattleCurveFollower2D
```

因此飞机会沿曲线终点切线继续飞行。

### 为什么按距离采样

不能简单使用：

```csharp
t += speed * Time.deltaTime;
```

贝塞尔曲线上相同的 `t` 增量不代表相同的实际距离，会造成飞机忽快忽慢。

当前设计把曲线采样为多个线段，并记录累计长度：

```text
实际飞行距离
→ 找到所在采样段
→ 在线段中插值位置
```

推荐采样数量：

```text
Sample Count = 32
```

推荐初始权重：

| 机型 | 权重 | 长期概率 |
|---|---:|---:|
| Normal | 60 | 约 60% |

## 15. Runtime 生成逻辑

脚本：

```text
Assets/Scripts/Battle/Debug/BattleDebugRuntime.cs
```

主要引用：

```text
Fighter Prefab
Player Fighter Definition
Enemy Fighter Definition
Player Spawn Pool
Enemy Spawn Pool
Player Spawn Point
Enemy Spawn Point
Curve Line
Fighter Container
```

双方可以暂时共用：

```text
DefaultFighterSpawnPool
```

### 指定机型生成

```text
玩家：使用调试窗口选中的 Player Fighter Definition
敌人：使用调试窗口选中的 Enemy Fighter Definition
```

### 随机机型生成

```text
玩家：每架独立从 Player Spawn Pool 抽取
敌人：每架独立从 Enemy Spawn Pool 抽取
```

随机选择必须放在批量生成循环内部：

```csharp
for (int index = 0; index < count; index++)
{
    if (spawnPool.TryGetRandom(
            out FighterDefinition definition))
    {
        SpawnFighter(definition);
    }
}
```

这样十架飞机会抽取十次，而不是整批只抽取一次。

批量生成建议保留间隔：

```text
Spawn Interval = 0.15 秒
```

否则同一路径上的飞机会完全重叠，看起来像只有一架。

9. 实现护盾战斗机的专属能力。
10. 实现冲锋战斗机的专属行为。
11. 将调试 Runtime 重构为正式玩家与敌人 Spawner。
12. 在关卡或波次数据中配置不同的 FighterSpawnPool。

### 推荐的阵营结构

后续可加入：

```csharp
public enum FighterFaction
{
    Player,
    Enemy
}
```

飞机实例保存阵营：

```text
Fighter2D
├── Definition
├── Faction
├── Current Health
└── Current movement state
```

这样碰撞和子弹伤害判断不需要依赖颜色或对象名称。

### 推荐的正式生成器结构

调试稳定后，可以将生成职责从 `BattleDebugRuntime` 提取到：

```text
FighterSpawner2D
├── Spawn Point
├── Faction
├── Spawn Pool
├── Faction Color
└── Curve Provider
```

然后：

```text
BattleDebugRuntime
└── 只调用 PlayerSpawner 和 EnemySpawner
```

这会使调试工具和正式玩法共用同一套生成接口。

## 19. 核心设计原则总结

```text
ScriptableObject 保存静态配置
MonoBehaviour 保存单个实例状态
Spawner 决定阵营、位置和生成规则
Curve 系统决定飞行路径
DirectionalMover2D 决定直线速度和方向
EditorWindow 只通过 Runtime 桥接控制游戏
```

飞机机型数据、阵营和生成概率彼此独立：

```text
FighterDefinition
        │
        ├── 被 Player Spawner 使用 → 淡蓝色
        │
        └── 被 Enemy Spawner 使用  → 淡红色

FighterSpawnPool
        └── 决定不同 FighterDefinition 的出现概率
```

这一结构能够支持后续新增更多机型、不同关卡权重、玩家和敌方共用机型，以及独立的飞机特殊能力。
