请为 Unity 编写一个可直接使用的 EditorWindow 调试工具。

要求：

- 使用 C# 和 Unity 内置 `EditorWindow` / IMGUI。
- `EditorWindow` 脚本放在 `Assets/Editor` 目录下。

- 调试工具包含三个独立的 `EditorWindow`：
  - **程序测试面板**：用于验证游戏功能是否正常，例如生成敌人、触发事件、切换状态或检查运行时数据。
  - **玩法设计面板**：用于验证和调整游戏设计是否合理、平衡，例如调整难度曲线、数值参数或关卡节奏。
  - **视效调整面板**：用于实时查看和调整游戏内视觉效果相关参数，例如特效强度、颜色、透明度、粒子表现、后处理参数或其他视觉表现参数。

- 三个 `EditorWindow` 在进入 Play Mode 后必须停靠在同一个 Unity Dock Area 中，作为三个并列的**停靠窗口标签页**显示。

### Play Mode 自动停靠

- 进入 Play Mode 前关闭已打开的三个 Center 面板，避免沿用旧布局。
- Runtime 启动后先创建程序测试面板，再创建玩法设计面板和视效调整面板，并将后两个面板停靠到程序测试面板所在的同一个 Dock Area。
- 三个 Center 面板在 Play Mode 中必须处于同一个 Dock Area。首次停靠未完成时，应通过延迟执行或重试机制继续完成停靠，不能以三个独立浮动窗口作为最终状态。
- 只有在确认三个 Center 面板均位于同一个 Dock Area 后，才视为 Play Mode 面板初始化完成。
- 此行为仅在 Unity Editor 的 Play Mode 生效，不影响导出后的 Player。

- 所有具体功能的调试界面不再单独创建 `EditorWindow`，而是作为所属 Center 面板中的**窗口内部功能标签页**。

- 本文中的标签页分为两类：
  - **停靠窗口标签页**：程序测试面板、玩法设计面板、视效调整面板。
  - **窗口内部功能标签页**：Runtime、数值、难度曲线、视觉效果参数等具体调试功能。

- 除非具体需求特别说明，新编写的功能标签页默认放在**程序测试面板**中。

- 与游戏视觉效果调整直接相关的功能标签页，应放在**视效调整面板**中。

- 新功能标签页完成后，应设为所属 Center 面板最新的默认内部标签页；打开该面板时优先显示它，直到后续有其他标签页被设为默认页。

- 创建独立的 Runtime 层，用于连接功能标签页与游戏运行时实例，并提供稳定的调试桥接接口。

- Runtime 层脚本放在普通运行时代码目录中，不得放在 `Assets/Editor` 下，也不得引用 `UnityEditor`。

- 为三个 Center 面板提供 `MenuItem` 入口。具体功能标签页也可以提供菜单入口，用于打开所属 Center、激活对应停靠窗口标签页并切换到指定内部标签页。

- 进入 Play Mode 并启动对应 Runtime 实例后，由 Runtime 层请求自动打开所属 Center，激活对应停靠窗口标签页，并切换到对应内部功能标签页。

- 退出 Play Mode 时，三个 Center 面板应自动关闭。

- 单个 Runtime 实例销毁时，只清理与该实例相关的绑定和状态，不应影响同一 Center 或其他 Center 中的其他功能标签页。某个 Center 已无有效调试目标时，可以只关闭该 Center。

- 每个 Center 面板只能存在一个窗口实例。避免因脚本重编译、场景切换、重复初始化或多个 Runtime 实例注册而重复打开窗口、重复注册标签页或重复创建绑定。

- 主要用于 Play Mode 下实时查看和控制游戏数据。

- 功能标签页只调用 Runtime 桥接层或现有业务接口，不直接修改系统内部数据结构。

### GameData 配置与保存

- 凡是支持保存参数、且这些参数调整完成后会作为游戏实际运行参数使用的功能标签页，应使用正式的 **GameData 配置资源**。调试面板只是这些配置资源的编辑入口，不应再维护一套与游戏正式数据并行的 DebugConfig。

- 正式配置资源统一存放在 `Assets/GameData` 下，并可按功能类别继续细分目录，例如：
  - 玩法、数值、难度等配置：`Assets/GameData/Gameplay/`
  - 视觉效果相关配置：`Assets/GameData/Visual/`
  - 其他系统配置：`Assets/GameData/<Category>/`
  - 如某个类别下配置较多，可以继续按具体系统或功能名称建立子目录。

- 新增一个具有保存功能的功能标签页时，必须为该功能定义一个明确的**默认配置资源**及默认保存路径。首次创建或首次打开该功能标签页时：
  - 优先查找并读取该功能对应的默认配置资源。
  - 如果默认配置资源不存在，则自动创建所需的 `GameData` 分类目录和默认配置资源。
  - 默认配置创建完成后立即将其设为当前保存目标，并从该配置加载编辑草稿。
  - 后续再次打开该功能标签页时，应直接读取已有默认配置，不得重复创建配置资源。
  - 默认配置资源属于游戏正式数据；默认配置的初始值应来自该配置类型定义的稳定默认值。除非具体功能明确要求，不应把场景中临时变化、随机结果或尚未确认的运行时状态自动写入默认配置。

- 游戏运行时应直接使用对应的 GameData 配置作为正式参数来源。调试面板中确认后的参数可以通过 Runtime 桥接层立即应用到当前运行实例；保存后的配置则作为后续运行、重新进入 Play Mode 或正式游戏加载时使用的数据来源。

- 支持保存参数的功能标签页，应区分以下操作：
  - **应用到运行时**：通过 Runtime 桥接层使当前编辑草稿立即生效，但不修改配置资源。
  - **保存**：将当前编辑草稿保存到当前已选择的配置资源；默认情况下当前目标为该功能的默认 GameData 配置。
  - **另存为**：在对应的 `GameData` 分类目录下创建新的配置资源，并将新资源切换为当前保存目标。纯测试用途、不会作为游戏正式参数使用的预设，可以由具体功能明确保存到独立的测试预设目录，但不得与正式 GameData 混淆。
  - **还原**：放弃未保存修改，重新从当前配置资源加载编辑草稿。

- 功能标签页编辑参数时，应维护独立的编辑草稿，不应在字段或 Slider 变化时直接修改正式配置资源。

- 面板应明确显示当前保存目标和未保存状态。玩法设计参数保存为对应的 Gameplay GameData，视效调整参数保存为对应的 Visual GameData；其他会直接参与游戏运行的参数也应保存到相应的 GameData 分类目录。面板 UI 状态、窗口布局、当前选中标签、折叠状态和个人使用习惯不得写入正式 GameData。

- 配置资源选择控件、当前保存目标、未保存状态，以及 **应用到运行时 / 保存 / 另存为 / 还原** 等操作应统一放在所属功能标签页的内容区顶部，并位于具体参数编辑区域之前。切换窗口内部功能标签页时，该顶部区域应显示当前标签页对应的配置资源、保存状态和操作，避免不同功能标签页之间误用保存目标。

- 保存前应校验参数合法性和关联关系；校验失败时禁止保存并显示明确提示。修改 Unity 配置资源时，应支持 Undo，并正确调用 `EditorUtility.SetDirty` 和 `AssetDatabase.SaveAssets`。

- 默认配置的查找、创建、目录创建、加载、保存、另存为、校验和还原应由 Editor 侧的功能标签页或独立配置服务负责。Runtime 层只负责读取正式运行数据、接收编辑草稿并应用到运行时实例，不得调用 `AssetDatabase`、`EditorPrefs` 或其他 `UnityEditor` API。

- Center 面板可以统一封装保存工具栏的公共样式和绘制框架，但工具栏实际显示的配置资源、保存状态和操作必须对应当前激活的功能标签页；具体参数的加载、校验、应用、保存和还原逻辑应由对应功能标签页或独立配置服务负责。

- 做好空引用、未进入 Play Mode、目标对象丢失、场景切换、Runtime 实例销毁和当前标签页不可用等情况的提示与保护。

- Center 面板需要实时刷新，但不要把复杂逻辑放在 `OnGUI` 中；功能标签页只负责界面绘制和调用稳定接口。

- Center 面板的创建、停靠、激活、自动打开、自动关闭、内部标签页注册、切换和默认页管理应集中处理，避免业务代码直接依赖具体的 `EditorWindow` 类型。

- 停靠实现应优先使用 Unity 公开 API。由于三个 Center 面板在 Play Mode 中必须位于同一个 Dock Area，如果当前 Unity 版本的公开 API 无法保证自动停靠，可以仅在 Editor 停靠管理代码中使用最小范围、可封装且带版本保护的反射作为兜底；不得让业务功能或 Runtime 层依赖 UnityEditor 内部类型。

- 代码应完整、可编译，并附上简短的目录结构和使用说明。

- 优先保持实现简单清晰，不要引入第三方插件或不必要的架构。
