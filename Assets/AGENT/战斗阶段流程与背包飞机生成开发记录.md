# 战斗阶段流程与背包飞机生成开发记录

## 1. 开发日期

2026-07-24

## 2. 本阶段目标

本阶段为游戏对局建立统一的战斗流程状态，并将现有背包物品冷却接入飞机生成。

主要完成内容：

- 对局分为“准备阶段”和“战斗阶段”。
- 提供全局 `BattleFlowController` 作为唯一阶段状态源。
- 背包、商店、飞机战斗逻辑和调试窗口监听统一阶段状态。
- `BackpackDebugScene` 增加当前阶段标签和玩家飞机生成点。
- 调试面板增加阶段切换按钮。
- 飞机和子弹进入准备阶段时渐隐销毁。
- 飞机物品在战斗阶段循环冷却，并在冷却结束后生成飞机。
- 背包通过生成队列保证任意两架飞机至少间隔 0.1 秒生成。
- 飞机生成时读取相邻装备，并挂载装备配置的粒子效果。
- 相同粒子效果只挂载一次。

测试场景：

```text
Assets/Scenes/BackpackDebugScene.unity
```

## 3. 战斗流程架构

核心脚本：

```text
Assets/Scripts/Battle/Flow/
├── BattlePhase.cs
├── BattleFlowController.cs
└── BattleFadeOut2D.cs
```

### 3.1 BattlePhase

`BattlePhase` 定义两个正式阶段：

```csharp
public enum BattlePhase
{
    Preparation,
    Combat,
}
```

显示名称对应：

| 枚举 | 游戏内名称 |
|---|---|
| `Preparation` | 准备阶段 |
| `Combat` | 战斗阶段 |

### 3.2 BattleFlowController

`BattleFlowController` 是整个对局的唯一阶段状态源。

对外提供：

| 成员 | 作用 |
|---|---|
| `Instance` | 当前全局控制器 |
| `CurrentPhase` | 当前阶段 |
| `IsCombatPhase` | 当前是否处于战斗阶段 |
| `PhaseChanged` | 阶段发生改变时通知监听者 |
| `SetPhase(...)` | 设置指定阶段 |
| `TogglePhase()` | 在准备与战斗阶段之间切换 |

控制器在场景加载前自动创建，并使用 `DontDestroyOnLoad` 跨场景保留。其他组件只读取阶段或监听 `PhaseChanged`，不依赖调试窗口。

调用方向：

```text
调试按钮或正式游戏流程
          ↓
BattleFlowController
          ↓ PhaseChanged
背包 / 商店 / 物品冷却 / 飞机战斗逻辑
```

调试窗口只是阶段切换入口之一。以后制作正式关卡时，可以由倒计时、玩家确认按钮或关卡控制器调用同一个 `SetPhase(...)` 接口。

## 4. 准备阶段规则

进入 `Preparation` 后：

- 玩家可以拖动背包物品。
- 商店显示。
- 可以刷新商店、购买物品和把物品拖入垃圾桶删除。
- 所有背包物品停止冷却，并恢复为完成状态。
- 飞机物品不会生成飞机。
- 飞机不会继续索敌或生成子弹。
- 场上现存飞机和子弹进入渐隐状态。

### 4.1 渐隐状态

渐隐由 `BattleFadeOut2D` 负责。

进入渐隐状态后：

1. 禁用飞机的 `FighterCombat2D`。
2. 禁用物体及其子节点的所有 `Collider2D`。
3. 飞机或子弹继续按照原方向移动。
4. 停止粒子系统继续发射新粒子。
5. 所有 `SpriteRenderer` 的透明度逐渐降低到 0。
6. 渐隐结束后销毁整个物体。

禁用碰撞后，渐隐对象不会造成伤害、受到伤害或触发新的碰撞响应。

`BattleFlowController` 进入准备阶段时会查找：

```text
Fighter2D
Projectile2D
```

并让所有仍存在的对象开始渐隐。

---

## 5. 战斗阶段规则

进入 `Combat` 后：

- 背包物品停止响应拖拽、点击和射线操作。
- 商店隐藏。
- 商店刷新操作不再生效。
- 所有可进入冷却的飞机物品开始冷却。
- 飞机物品冷却结束后生成对应飞机。
- 只要仍处于战斗阶段，生成完成后物品会重新进入下一轮冷却。
- 飞机允许索敌、停止飞行、瞄准和发射子弹。

物品冷却与飞机生成流程：

```text
进入战斗阶段
    ↓
飞机物品 EnterCooldown
    ↓
冷却遮罩逐渐消失
    ↓
CooldownCompleted
    ↓
加入背包飞机生成队列
    ↓
按至少 0.1 秒间隔调用 SpawnFighter
    ↓
读取相邻装备并挂载粒子
    ↓
物品重新进入下一轮冷却
```

## 7. 飞机生成间隔

`BackpackDebugRuntime` 使用一个背包级的先进先出队列保存待生成飞机：

```text
pendingFighterSpawns
```

生成间隔字段：

```text
Fighter Spawn Interval: 0.1
```

当多个飞机物品在同一帧完成冷却时：

1. 每个物品只把自己的 `ItemInstance` 加入队列。
2. 第一个请求立即生成飞机。
3. 如果队列中还有请求，则等待至少 `0.1` 秒。
4. 再生成下一架飞机，直到队列清空。

因此即使两个或更多物品同时结束冷却，也不会在同一时间点重叠生成飞机。

切回准备阶段时会立即：

- 清空尚未处理的飞机生成请求。
- 停止当前生成队列协程。
- 阻止准备阶段补生成此前排队的飞机。

该队列属于整个背包，而不是单个物品，因此能够统一约束不同飞机物品之间的生成间隔。

## 9. 相邻装备读取规则

相邻查询复用 `BackpackController` 已有接口：

```csharp
GetAdjacentItems(...)
GetAdjacentEquipmentItems(...)
```

相邻仅计算四个正方向：

```text
    上
左  飞机  右
    下
```

斜角接触不算相邻。

多格飞机会检查它占用的每一个格子，因此装备接触飞机任意外边缘都可以被识别。

### 粒子去重

生成飞机时使用 `HashSet<GameObject>` 记录已挂载的粒子 Prefab。

例如飞机同时邻接两个都配置为橙色粒子的装备：

```text
装备A：VFX_Particles_Orange
装备B：VFX_Particles_Orange
```

最终只会实例化一个橙色粒子。

如果相邻装备分别配置为橙色和粉色粒子，则两种不同粒子都可以各挂载一个。

挂载后的节点命名格式：

```text
VFX_Particles_Orange (Equipment)
```

可以在运行时 Hierarchy 展开飞机检查读取结果。

## 12. 手工验收流程

### 12.1 首次配置

1. 打开 `BackpackDebugScene`。
2. 等待脚本编译完成。
3. 执行：

   ```text
   Tools → Backpack → Setup Battle Flow Debug Scene
   ```

4. 保存场景。
5. 打开 Backpack Debug 窗口。
6. 进入 Play Mode。

### 12.2 准备阶段

确认：

- 标签显示“当前阶段：准备阶段”。
- 商店可见并且可以刷新。
- 商店物品可以拖入背包。
- 背包物品可以移动和删除。
- 飞机物品没有运行冷却。

### 12.3 战斗阶段

点击“切换阶段”，确认：

- 标签显示“当前阶段：战斗阶段”。
- 商店隐藏。
- 背包物品无法拖动。
- 飞机物品开始显示冷却。
- 冷却完成后，飞机从 `PlayerFighterSpawnPoint` 向上生成。

### 12.4 相邻装备

1. 把飞机物品与装备物品上下或左右相邻摆放。
2. 进入战斗阶段。
3. 等待飞机生成。
4. 在 Hierarchy 展开新飞机。
5. 确认存在：

   ```text
   VFX_Particles_Orange (Equipment)
   ```

6. 使用两个相同粒子的相邻装备，确认飞机仍只有一个对应粒子节点。

### 12.5 渐隐

1. 在战斗阶段等待飞机和子弹出现。
2. 切换回准备阶段。
3. 确认飞机和子弹继续移动。
4. 确认它们不再发生碰撞或造成伤害。
5. 确认透明度逐渐降为 0 并销毁。

---

### 12.6 同时完成冷却

1. 在背包中放置两个冷却时间相同的飞机物品。
2. 进入战斗阶段。
3. 等待两个物品同时完成冷却。
4. 确认第一架飞机生成后，第二架不会在同一时间点出现。
5. 确认两架飞机的生成时间至少相差 `0.1` 秒。
6. 在仍有飞机排队时切回准备阶段，确认排队飞机不会继续生成。

## 15. 统一背包战斗组件重构

背包战斗逻辑已经从 `BackpackDebugRuntime` 中提取，正式结构为：

```text
BackpackController
        ↓
BackpackCombatController
        ↓
BackpackFighterSpawner
```

### 15.1 BackpackController

继续作为纯 C# 占格数据模型，负责：

- 7×4 背包格子。
- 放置、移动、删除和清空物品。
- 查询相邻物品与相邻装备。
- 提供 `Contains(...)` 验证物品是否仍属于背包。
- 发出物品添加、移动、删除和背包清空事件。

### 15.2 ItemInstance

冷却状态已经从 `ItemView` 移入 `ItemInstance`：

```text
IsCoolingDown
RemainingCooldown
CooldownProgress
BeginCooldown()
TickCooldown()
ResetCooldown()
```

因此没有 UI 的敌人背包也能正常冷却和生成飞机。`ItemView` 只读取状态并更新冷却材质，不再运行冷却协程或生成飞机。

### 15.3 BackpackCombatController

这是正式背包的战斗入口：

- 创建并持有 `BackpackController`。
- 从同物体的 `FactionMember` 读取阵营。
- 保存默认物品布局。
- 监听准备/战斗阶段。
- 战斗阶段推进所有飞机物品冷却。
- 冷却完成后向生成器提交请求。
- 对外提供添加、放置、移动、删除、清空和恢复默认布局接口。

正式系统和调试工具都必须通过该组件修改背包。

### 15.4 BackpackFighterSpawner

生成器负责：

- 使用统一 FIFO 队列处理飞机请求。
- 任意两架飞机至少间隔 `0.1` 秒。
- 出队前验证物品仍在原背包中。
- 准备阶段或组件禁用时清空队列。
- 根据阵营自动选择玩家向上、敌人向下。
- 自动寻找最近的敌对背包作为曲线终点。
- 找不到敌对背包时沿默认方向直飞。
- 读取相邻装备并对粒子 Prefab 去重。

公开调试信息：

```text
PendingCount
SpawnInterval
LastSpawnTime
```

### 15.5 玩家与敌人的最简配置

`BattleBackpackBase.prefab` 统一保存：

- `BackpackCombatController`
- `BackpackFighterSpawner`
- Fighter Prefab
- 默认物品布局
- 飞机生成点
- 生成间隔与颜色

玩家和敌人只需要在 `FactionMember` 中选择：

```text
Player
Enemy
```

方向、颜色、碰撞阵营、目标选择和飞机生成都会自动使用对应阵营。

### 15.6 调试窗口

新版 Battle Debug 不再访问旧 `BattleBackpack`。

窗口会直接发现当前场景中的所有 `BackpackCombatController`，并显示：

- 背包名称和阵营。
- 当前战斗阶段。
- 物品数量与冷却进度。
- 待生成飞机数量。
- 生成间隔和最近生成时间。
- 默认布局恢复与物品增删。

旧的 `BattleBackpack`、`BattleBackpackItem` 和 `BattleBackpackOwner` 已停止使用并移除。
