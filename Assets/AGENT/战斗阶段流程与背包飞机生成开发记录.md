# 战斗阶段流程与背包飞机生成开发记录

## 1. 开发日期

2026-07-24

## 2. 本阶段目标

本阶段为游戏对局建立统一的战斗流程状态，并将现有背包物品冷却接入飞机生成。

主要完成内容：

- 对局分为“准备阶段”和“战斗阶段”。
- 提供全局 `BattleFlowController` 作为唯一阶段状态源。
- 背包、商店、飞机战斗逻辑和调试窗口监听统一阶段状态。
- `BackpackDebugScene` 增加当前阶段标签和玩家飞机生成点。
- 调试面板增加阶段切换按钮。
- 飞机和子弹进入准备阶段时渐隐销毁。
- 飞机物品在战斗阶段循环冷却，并在冷却结束后生成飞机。
- 飞机生成时读取相邻装备，并挂载装备配置的粒子效果。
- 相同粒子效果只挂载一次。

测试场景：

```text
Assets/Scenes/BackpackDebugScene.unity
```

## 3. 战斗流程架构

核心脚本：

```text
Assets/Scripts/Battle/Flow/
├── BattlePhase.cs
├── BattleFlowController.cs
└── BattleFadeOut2D.cs
```

### 3.1 BattlePhase

`BattlePhase` 定义两个正式阶段：

```csharp
public enum BattlePhase
{
    Preparation,
    Combat,
}
```

显示名称对应：

| 枚举 | 游戏内名称 |
|---|---|
| `Preparation` | 准备阶段 |
| `Combat` | 战斗阶段 |

### 3.2 BattleFlowController

`BattleFlowController` 是整个对局的唯一阶段状态源。

对外提供：

| 成员 | 作用 |
|---|---|
| `Instance` | 当前全局控制器 |
| `CurrentPhase` | 当前阶段 |
| `IsCombatPhase` | 当前是否处于战斗阶段 |
| `PhaseChanged` | 阶段发生改变时通知监听者 |
| `SetPhase(...)` | 设置指定阶段 |
| `TogglePhase()` | 在准备与战斗阶段之间切换 |

控制器在场景加载前自动创建，并使用 `DontDestroyOnLoad` 跨场景保留。其他组件只读取阶段或监听 `PhaseChanged`，不依赖调试窗口。

调用方向：

```text
调试按钮或正式游戏流程
          ↓
BattleFlowController
          ↓ PhaseChanged
背包 / 商店 / 物品冷却 / 飞机战斗逻辑
```

调试窗口只是阶段切换入口之一。以后制作正式关卡时，可以由倒计时、玩家确认按钮或关卡控制器调用同一个 `SetPhase(...)` 接口。

## 4. 准备阶段规则

进入 `Preparation` 后：

- 玩家可以拖动背包物品。
- 商店显示。
- 可以刷新商店、购买物品和把物品拖入垃圾桶删除。
- 所有背包物品停止冷却，并恢复为完成状态。
- 飞机物品不会生成飞机。
- 飞机不会继续索敌或生成子弹。
- 场上现存飞机和子弹进入渐隐状态。

### 4.1 渐隐状态

渐隐由 `BattleFadeOut2D` 负责。

进入渐隐状态后：

1. 禁用飞机的 `FighterCombat2D`。
2. 禁用物体及其子节点的所有 `Collider2D`。
3. 飞机或子弹继续按照原方向移动。
4. 停止粒子系统继续发射新粒子。
5. 所有 `SpriteRenderer` 的透明度逐渐降低到 0。
6. 渐隐结束后销毁整个物体。

禁用碰撞后，渐隐对象不会造成伤害、受到伤害或触发新的碰撞响应。

`BattleFlowController` 进入准备阶段时会查找：

```text
Fighter2D
Projectile2D
```

并让所有仍存在的对象开始渐隐。

## 5. 战斗阶段规则

进入 `Combat` 后：

- 背包物品停止响应拖拽、点击和射线操作。
- 商店隐藏。
- 商店刷新操作不再生效。
- 所有可进入冷却的飞机物品开始冷却。
- 飞机物品冷却结束后生成对应飞机。
- 只要仍处于战斗阶段，生成完成后物品会重新进入下一轮冷却。
- 飞机允许索敌、停止飞行、瞄准和发射子弹。

物品冷却与飞机生成流程：

```text
进入战斗阶段
    ↓
飞机物品 EnterCooldown
    ↓
冷却遮罩逐渐消失
    ↓
CooldownCompleted
    ↓
BackpackDebugRuntime.SpawnFighter
    ↓
读取相邻装备并挂载粒子
    ↓
物品重新进入下一轮冷却
```

## 6. 背包场景接入

主要修改脚本：

```text
Assets/Scripts/BackpackPrototype/
├── BackpackDebugRuntime.cs
├── ItemData.cs
└── ItemView.cs
```

### 6.1 BackpackDebugRuntime

新增场景引用：

| 字段 | 用途 |
|---|---|
| `Phase Label` | 显示当前阶段 |
| `Shop Root` | 准备阶段显示、战斗阶段隐藏 |
| `Player Fighter Spawn Point` | 玩家飞机生成位置 |
| `Fighter Prefab` | 实例化使用的飞机 Prefab |
| `Fighter Container` | 可选的飞机父节点 |
| `Player Fighter Color` | 玩家阵营颜色 |

新增主要职责：

- 监听 `BattleFlowController.PhaseChanged`。
- 切换商店可见性。
- 切换所有物品的交互状态。
- 开始或停止物品冷却。
- 处理 `CooldownCompleted`。
- 生成玩家飞机。
- 查询并挂载相邻装备效果。

### 6.2 ItemView

`ItemView` 新增：

| 接口 | 作用 |
|---|---|
| `CooldownCompleted` | 本轮冷却完成事件 |
| `StopCooldown(...)` | 停止冷却并重置遮罩 |
| `SetInteractionEnabled(...)` | 统一控制拖拽和射线交互 |

`OnBeginDrag(...)` 还会再次检查当前阶段，确保战斗阶段无法开始拖拽。

## 7. 飞机与装备物品配置

`ItemData` 新增两个战斗配置字段：

| 字段 | 使用物品 | 作用 |
|---|---|---|
| `Fighter Definition` | 飞机物品 | 冷却完成后生成的飞机种类 |
| `Equipment Effect Prefab` | 装备物品 | 相邻飞机生成时挂载的粒子效果 |

### 7.1 默认飞机

现有飞机物品默认绑定：

```text
Assets/Settings/Battle/Fighters/Fighter_01_Normal.asset
```

已经配置的资源：

```text
Aircraft_First.asset
Aircraft_L.asset
```

以后可以为不同飞机物品指定不同的 `FighterDefinition`。

### 7.2 默认装备粒子

现有装备物品默认绑定：

```text
Assets/Prefabs/VFX/Particles/VFX_Particles_Orange.prefab
```

已经配置的资源：

```text
Equipment_First.asset
Equipment_1x2.asset
```

以后可以为不同装备指定不同的粒子 Prefab。

## 8. 相邻装备读取规则

相邻查询复用 `BackpackController` 已有接口：

```csharp
GetAdjacentItems(...)
GetAdjacentEquipmentItems(...)
```

相邻仅计算四个正方向：

```text
    上
左  飞机  右
    下
```

斜角接触不算相邻。

多格飞机会检查它占用的每一个格子，因此装备接触飞机任意外边缘都可以被识别。

### 粒子去重

生成飞机时使用 `HashSet<GameObject>` 记录已挂载的粒子 Prefab。

例如飞机同时邻接两个都配置为橙色粒子的装备：

```text
装备A：VFX_Particles_Orange
装备B：VFX_Particles_Orange
```

最终只会实例化一个橙色粒子。

如果相邻装备分别配置为橙色和粉色粒子，则两种不同粒子都可以各挂载一个。

挂载后的节点命名格式：

```text
VFX_Particles_Orange (Equipment)
```

可以在运行时 Hierarchy 展开飞机检查读取结果。

## 9. BackpackDebugScene 专用内容

以下内容只属于背包测试场景，不进入正式业务控制器：

- `BattlePhaseLabel`
- `PlayerFighterSpawnPoint` 的可视化图片
- Backpack Debug 编辑器窗口中的“切换阶段”按钮
- 场景快速配置菜单

场景配置脚本：

```text
Assets/Editor/BackpackDebug/
└── BackpackBattleFlowSceneSetup.cs
```

菜单入口：

```text
Tools → Backpack → Setup Battle Flow Debug Scene
```

执行后会：

1. 在背包左上方创建 `BattlePhaseLabel`。
2. 创建带默认飞机图片的 `PlayerFighterSpawnPoint`。
3. 配置 `BackpackDebugRuntime` 的标签、商店、生成点和飞机 Prefab 引用。
4. 为飞机物品配置默认 `FighterDefinition`。
5. 为装备物品配置默认粒子 Prefab。
6. 保存 `BackpackDebugScene` 和物品资源。

该菜单可以重复执行，不会重复创建同名标签和生成点。

## 10. 调试面板

打开方式：

```text
Tools → Backpack → Backpack Debug
```

`Actions` 区域包含：

- 恢复默认背包。
- 刷新商店物品。
- 切换阶段。
- 显示当前阶段。

“切换阶段”调用：

```csharp
BattleFlowController.Instance.TogglePhase();
```

窗口不会保存另一份阶段变量。

## 11. 手工验收流程

### 11.1 首次配置

1. 打开 `BackpackDebugScene`。
2. 等待脚本编译完成。
3. 执行：

   ```text
   Tools → Backpack → Setup Battle Flow Debug Scene
   ```

4. 保存场景。
5. 打开 Backpack Debug 窗口。
6. 进入 Play Mode。

### 11.2 准备阶段

确认：

- 标签显示“当前阶段：准备阶段”。
- 商店可见并且可以刷新。
- 商店物品可以拖入背包。
- 背包物品可以移动和删除。
- 飞机物品没有运行冷却。

### 11.3 战斗阶段

点击“切换阶段”，确认：

- 标签显示“当前阶段：战斗阶段”。
- 商店隐藏。
- 背包物品无法拖动。
- 飞机物品开始显示冷却。
- 冷却完成后，飞机从 `PlayerFighterSpawnPoint` 向上生成。

### 11.4 相邻装备

1. 把飞机物品与装备物品上下或左右相邻摆放。
2. 进入战斗阶段。
3. 等待飞机生成。
4. 在 Hierarchy 展开新飞机。
5. 确认存在：

   ```text
   VFX_Particles_Orange (Equipment)
   ```

6. 使用两个相同粒子的相邻装备，确认飞机仍只有一个对应粒子节点。

### 11.5 渐隐

1. 在战斗阶段等待飞机和子弹出现。
2. 切换回准备阶段。
3. 确认飞机和子弹继续移动。
4. 确认它们不再发生碰撞或造成伤害。
5. 确认透明度逐渐降为 0 并销毁。

## 13. 后续建议

1. 正式关卡控制器通过 `BattleFlowController.SetPhase(...)` 切换阶段。
2. 将商店正式逻辑也直接监听 `PhaseChanged`，逐步脱离 Debug Runtime。
3. 将背包飞机生成职责从 `BackpackDebugRuntime` 提取为正式 `BackpackBattleSpawner`。
4. 为阶段切换、冷却暂停、邻接粒子去重和渐隐碰撞禁用补充 PlayMode 测试。
5. 增加战斗阶段结束条件和准备阶段倒计时。
6. 根据装备类型扩展除粒子之外的飞机属性修改效果。
