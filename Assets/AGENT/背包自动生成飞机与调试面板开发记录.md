# 背包自动生成飞机与调试面板开发记录

## 1. 开发目标

在 `SampleScene` 现有玩家、敌人和飞机生成功能上，增加一套背包自动生成系统，并通过 Unity `EditorWindow` 实时查看和修改运行时背包。

第一版实现内容：

- 玩家和敌人各自拥有独立背包。
- 每个背包默认有 3 个普通战斗机物品。
- 默认物品的循环冷却时间为 3 秒。
- 3 个默认物品的首次冷却错开，分别在约第 1、2、3 秒完成。
- 物品进入 Play Mode 后自动充能。
- 充能完成后生成对应飞机，然后重新进入冷却。
- 调试面板实时显示物品名称、冷却进度条和删除按钮。
- 背包修改器可以选择玩家或敌人、飞机类型和自定义 CD，再添加新物品。
- 调试窗口在对应 Runtime 实例启动时自动打开，退出 Play Mode 或 Runtime 销毁时自动关闭。

物品的长期设计包含“机体”和“装备”两类。当前第一版只实现机体，即使用 `FighterDefinition` 的飞机物品；装备的数据和运行逻辑暂未实现。

## 2. 主要场景和依赖

主要调试场景：

```text
Assets/Scenes/SampleScene.unity
```

背包系统复用现有战斗生成功能，包括：

- `BattleDebugRuntime`：战斗运行时桥接与飞机生成入口。
- `FighterDefinition`：飞机的静态配置数据。
- `SpawnPlayerFighter(...)`：生成玩家飞机。
- `SpawnEnemyFighter(...)`：生成敌人飞机。
- `CurvedConnectionRenderer`：提供玩家飞机生成时使用的当前曲线值。

背包不直接 `Instantiate` 飞机，而是在物品完成冷却后通知 `BattleDebugRuntime`，再复用已有生成接口。

## 4. 系统架构

```text
BattleDebugWindow
├── 读取背包和物品状态
├── 绘制物品名称和进度条
└── 调用 BattleDebugRuntime 的添加/删除接口
               │
               ▼
BattleDebugRuntime
├── PlayerBackpack
├── EnemyBackpack
├── 每帧推进两个背包
├── 监听 ItemCharged
└── 调用现有飞机生成接口
               │
               ▼
BattleBackpack
├── 管理 BattleBackpackItem 列表
├── 推进所有物品冷却
├── 添加和删除物品
└── 在物品充能完成时发出 ItemCharged
               │
               ▼
BattleBackpackItem
├── FighterDefinition
├── CooldownDuration
├── RemainingCooldown
└── CooldownProgress
```

### 设计原则

- `BattleBackpackItem` 不负责生成飞机。
- `BattleBackpack` 不需要知道自己属于玩家还是敌人。
- `BattleDebugRuntime` 决定冷却完成后如何生成对应阵营的飞机。
- `BattleDebugWindow` 不直接修改背包内部列表，写操作经由 `BattleDebugRuntime` 对外接口完成。
- 复用现有 `FighterDefinition` 和飞机生成流程，不创建第二套飞机数据或生成器。

## 5. 背包物品

脚本：

```text
Assets/Scripts/Battle/Backpack/BattleBackpackItem.cs
```

`BattleBackpackItem` 表示背包中的一个运行时机体物品，主要数据为：

| 属性 | 含义 |
|---|---|
| `FighterDefinition` | 物品完成充能时要生成的飞机配置 |
| `DisplayName` | 调试面板显示名称，来自 `FighterDefinition.DisplayName` |
| `CooldownDuration` | 完整冷却时间 |
| `RemainingCooldown` | 当前剩余冷却时间 |
| `CooldownProgress` | 0—1 的充能进度 |

充能进度计算：

```text
CooldownProgress = 1 - RemainingCooldown / CooldownDuration
```

`Tick(deltaTime)` 每次减少剩余冷却。当剩余时间小于或等于 0 时：

1. 返回 `true`，表示本次冷却完成。
2. 将剩余时间重置为完整 CD。
3. 下一轮重新开始充能。

## 6. 背包容器

脚本：

```text
Assets/Scripts/Battle/Backpack/BattleBackpack.cs
```

`BattleBackpack` 是普通 C# 对象，不继承 `MonoBehaviour`，也不需要挂到 GameObject。

主要职责：

- 保存 `BattleBackpackItem` 列表。
- 使用 `Tick(deltaTime)` 推进所有物品。
- 通过 `AddFighter(...)` 添加机体物品。
- 通过 `RemoveItem(...)` 或 `RemoveAt(...)` 删除物品。
- 通过只读列表和查询接口向外提供物品状态。
- 物品完成冷却时发出 `ItemCharged` 事件。

背包本身不生成飞机，因此可以在未来复用于其他战斗运行时控制器。

## 7. Runtime 桥接与自动生成

脚本：

```text
Assets/Scripts/Battle/Debug/BattleDebugRuntime.cs
```

### 7.1 两个运行时背包

`BattleDebugRuntime` 创建并持有：

```csharp
private readonly BattleBackpack playerBackpack;
private readonly BattleBackpack enemyBackpack;
```

`Update()` 中使用 `Time.deltaTime` 推进两个背包，因此退出 Play Mode 或暂停游戏后不会继续充能。

### 7.2 默认配置

Runtime 启动时清空背包并重建默认物品。玩家和敌人分别添加 3 个当前默认 `FighterDefinition`。

默认 CD 由 Inspector 中的字段控制：

```csharp
[SerializeField, Min(0.1f)]
private float defaultBackpackCooldown = 3f;
```

当 CD 为 3 秒时，三个物品的首次剩余时间为：

| 物品 | 首次冷却 | 后续生成时刻示例 |
|---|---:|---|
| 1 | 1 秒 | 1、4、7… |
| 2 | 2 秒 | 2、5、8… |
| 3 | 3 秒 | 3、6、9… |

因此稳定运行时会每秒有一个默认物品完成充能。

### 7.3 冷却完成

Runtime 订阅两个背包的 `ItemCharged` 事件：

- 玩家物品完成时，使用当前 `curveLine.CurrentCurveValue` 生成玩家飞机。
- 敌人物品完成时，调用已有敌机生成方法，使用随机曲线值。
- Runtime 销毁时解除事件订阅。

### 7.4 稳定调试接口

`BattleDebugRuntime` 向调试窗口提供：

```csharp
GetBackpack(BattleBackpackOwner owner)
AddBackpackFighter(owner, definition, cooldown)
RemoveBackpackItem(owner, item)
```

`BattleBackpackOwner` 只包含：

```text
Player
Enemy
```

窗口不需要知道玩家和敌人背包字段的内部细节。

## 8. Battle Debug 窗口

脚本：

```text
Assets/Editor/BattleDebug/BattleDebugWindow.cs
```

菜单入口：

```text
Tools/Battle/Battle Debug
```

窗口包含三个主要栏位。

### 8.1 Player Backpack

显示玩家背包的所有物品。

每一行水平显示：

```text
物品名称 | 冷却进度条 | Delete 按钮
```

### 8.2 Enemy Backpack

与玩家背包布局一致，显示敌人物品的实时冷却。

### 8.3 Backpack Modifier

包含：

| 控件 | 作用 |
|---|---|
| `Target Backpack` | 选择 `Player` 或 `Enemy` |
| `Fighter` | 选择要添加的 `FighterDefinition` |
| `Cooldown` | 设置新物品的循环冷却 |
| `Add Fighter` | 向指定背包添加物品 |

新添加的物品会先进行一次完整充能，不会在添加后的下一帧立即生成飞机。

### 8.4 实时刷新

EditorWindow 约每 0.1 秒调用一次 `Repaint()`，以显示冷却进度。冷却计算不在 `OnGUI()` 中执行，`OnGUI()` 只读取已有 Runtime 状态并绘制界面。

窗口使用滚动区域，背包物品较多时仍可继续操作。

## 9. 窗口生命周期

脚本：

```text
Assets/Editor/BattleDebug/BattleDebugWindowLifecycle.cs
```

`BattleDebugWindowLifecycle` 集中管理自动打开和关闭，Runtime 代码不需要引用或认识 `EditorWindow`。

生命周期规则：

- 已进入 Play Mode 且 `BattleDebugRuntime.Instance` 出现时，自动打开窗口。
- Runtime 实例消失时，关闭所有 `BattleDebugWindow`。
- 退出 Play Mode 或返回 Edit Mode 时，关闭窗口。
- `GetWindow<BattleDebugWindow>()` 复用已有窗口，避免重复打开多个实例。
- 即使脚本重编译或窗口手动打开，监控逻辑仍会根据 Runtime 存在状态恢复正确结果。

## 10. 操作说明

### 使用默认背包

1. 打开 `Assets/Scenes/SampleScene.unity`。
2. 确认场景中 `BattleDebugRuntime` 的飞机 Prefab、玩家/敌人飞机配置、生成点和 Curve Line 已配置。
3. 将 `Default Backpack Cooldown` 保持为 `3`。
4. 进入 Play Mode。
5. 在自动打开的 Battle Debug 窗口中观察充能和飞机生成。

### 添加物品

1. 在 `Target Backpack` 选择玩家或敌人。
2. 在 `Fighter` 选择一个 `FighterDefinition` 资源。
3. 输入 `Cooldown`。
4. 点击 `Add Fighter`。
5. 新物品立即出现在指定背包中，并开始完整充能。

### 删除物品

点击物品行右侧的 `Delete`。物品会在当次 GUI 绘制结束后通过 Runtime 接口删除，避免在遍历列表时直接修改集合。

## 11. 验收清单

### 默认行为

- [ ] 玩家和敌人背包各有 3 个普通战斗机。
- [ ] 默认 CD 为 3 秒。
- [ ] 首次生成时间错开为约 1、2、3 秒。
- [ ] 冷却完成时生成对应阵营的飞机。
- [ ] 生成后物品重新进入冷却。

### 调试面板

- [ ] 进度条会在 Play Mode 中实时变化。
- [ ] 物品名称与 `FighterDefinition.DisplayName` 一致。
- [ ] 删除物品后，该物品不再生成飞机。
- [ ] 修改器可向玩家和敌人背包添加物品。
- [ ] 修改器可以选择不同飞机配置。
- [ ] 新增物品使用输入的 CD，并先经过一次完整充能。
- [ ] CD 为 0 或负数时被限制为至少 0.1 秒。

### 生命周期与异常保护

- [ ] Runtime 出现时只自动打开一个调试窗口。
- [ ] 退出 Play Mode 时窗口自动关闭。
- [ ] Runtime 缺失或配置不完整时显示提示，不抛出空引用异常。
- [ ] 场景切换或脚本重编译后不会重复打开多个窗口。

## 12. 第一版边界与后续方向

当前完成的是用于测试战斗生成节奏的第一版背包，存在以下明确边界：

- 只支持机体物品。
- 物品数据是 Play Mode 中的临时运行时数据，退出后不保存。
- 默认背包直接使用场景中已配置的玩家/敌人 `FighterDefinition`。
- 当前没有背包容量上限、数量堆叠、序列化或存档。
- 当前没有正式游戏 UI，只有 Unity Editor 调试窗口。

后续如果实现装备，建议先明确装备是独立周期触发、修改机体属性，还是与机体组合后才生效，再决定是否需要统一的物品基类或类型枚举。第一版不提前引入这些未确定抽象。

---

## 13. 总结

背包系统已经将“物品冷却”与“飞机生成”连接，并保持 Editor 层、Runtime 桥接层和背包数据层的职责分离。

当前实现已覆盖本阶段需要的默认背包、错开充能、循环生成、实时进度、物品删除和运行时添加功能。装备系统、正式背包 UI 与存档不属于本次开发范围。
