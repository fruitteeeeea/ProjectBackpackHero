# 风格倾向与背包冷却机制开发记录

## 1. 目标与范围

本轮为“玩法设计面板”增加了与“游戏节奏”并列的“风格倾向”标签页。该页管理全局战斗风格参数，并提供独立的配置资产、运行时草稿和保存流程。

同时，背包冷却不再固定为装备物品冷却，而是由风格配置选择“飞机物品冷却”或“装备物品冷却”。生成飞机时装备效果的继承规则也会跟随此选择变化。

## 2. 配置资产与默认值

配置类型：`StyleTendencyDebugSettings`  
不可变运行时值：`StyleTendencyMultipliers`  
运行时桥接：`StyleTendencyDebugRuntime`

预置资产：

- `Assets/Resources/StyleTendency/Strategy.asset`
- `Assets/Resources/StyleTendency/Arcade.asset`

运行时启动时从 `Resources/StyleTendency/Strategy` 读取默认值，因此默认编辑和加载的都是 Strategy。

两份配置的初始全局倍率均为 `1`。冷却方式预置不同：

| 配置 | 冷却物品方式 |
| --- | --- |
| Strategy | 装备物品冷却 |
| Arcade | 飞机物品冷却 |

> 当前 Strategy 资产中已有经过面板保存的其他倍率值；后续新增字段保持 `1`，不应为了初始化而覆盖已保存的设计参数。

## 3. 风格倾向面板

主入口在 `Assets/Editor/DebugCenterWindow.cs`，标签页实现位于：

```text
Assets/Editor/StyleTendencyDebug/StyleTendencyDebugWindow.cs
```

该页具备与“游戏节奏”一致的草稿编辑与持久化流程：

- 选择保存目标；切换目标会从该资产重载草稿。
- “应用到运行时”仅作用于本次 Play Mode，不写入资产。
- “保存”写入当前目标，“另存为”创建新资产，“还原”放弃草稿修改。
- 草稿与保存目标不一致时显示未保存状态。
- 点击“应用到运行时”后自动调用一次 `BattleFlowController.TogglePhase()`。
- “配置操作”下方有“阶段控制”区，可直接显示并切换当前战斗阶段。

### 冷却方式

“全局属性倍率”上方提供“物品冷却方式”：

- 飞机物品冷却
- 装备物品冷却

对应枚举定义：`Assets/Scripts/BackpackPrototype/CooldownItemType.cs`。

### 全局属性倍率

| 面板名称 | 运行时含义 | 范围 |
| --- | --- | --- |
| 物品冷却速度 | 冷却推进速度；数值越大越快 | 0.5–3 |
| 飞机索敌角度 | `TargetingArcAngle` 最终倍率，结果封顶 360° | 0.5–3 |
| 飞机攻击范围 | 基础攻击范围加随机偏移后再乘倍率 | 0.5–3 |
| 飞机射速 | 默认子弹和装备子弹的射击 Tick 倍率 | 0.2–2 |
| 飞机飞行速度 | 飞机基础速度、初始爆发和游戏节奏速度结算后的最终倍率 | 0.5–2 |
| 飞机存活时间 | 新生成飞机的 `Lifetime` 最终倍率 | 0.5–2 |
| 子弹速度 | 所有 `Projectile2D` 的发射速度最终倍率 | 0.5–1 |
| 子弹存活时间 | 新生成 `Projectile2D` 的 `Lifetime` 最终倍率 | 0.1–1 |

运行时不存在时，所有倍率查询回退为 `1`，冷却类型回退为装备物品冷却。

## 4. 阶段切换与生命恢复

`BattleFlowController` 在切换阶段时会遍历双方背包目标，并通过 `Health.ResetHealth()` 恢复全部血量，再执行原有的阶段切换流程。

## 5. 冷却与生成规则

核心冷却控制位于 `BackpackCombatController`。

### 进入战斗

- 仅当前 `CooldownItemType` 对应的物品开始完整冷却。
- 另一类型不会推进冷却。
- 战斗中放入的新物品，只有类型与当前冷却方式相同才会开始冷却。

### 运行时更改冷却方式

`StyleTendencyDebugRuntime.CooldownItemTypeChanged` 是专用事件。只有冷却类型实际变化时才触发，避免修改其他风格倍率时重置冷却。

战斗中切换类型会：

1. 清除待生成请求。
2. 重置所有物品的冷却状态。
3. 从完整 CD 开始为新的物品类型进行冷却。

### 飞机物品冷却

飞机物品结束冷却时，按自身 `SpawnCount` 发起生成请求：

- 生成的飞机保留默认子弹。
- 收集该飞机在背包中的全部相邻装备物品，并携带这些装备效果。

### 装备物品冷却

装备物品结束冷却时：

- 遍历其周围全部相邻飞机物品。
- 每一架飞机按该飞机物品自己的 `SpawnCount` 生成。
- 每架生成飞机只应用本次触发装备的子弹效果。
- 清除默认子弹。
- 没有相邻飞机时不生成任何请求。

生成请求会保留触发装备上下文，并在真正生成前验证触发物品、飞机物品仍在背包中且冷却模式未变化；失效组合不会使用过期邻接关系生成飞机。

## 6. 最终数值结算位置

风格倍率只在既有数值结算之后再乘一次，不替代游戏节奏职责。

- 物品冷却：先使用原始冷却时长与游戏节奏的冷却时长结算，再以风格冷却速度影响推进。
- 索敌角度：`FighterCombat2D` 使用区分后的有效索敌角度；索敌扇形和 Gizmo 使用同一数值。
- 攻击范围：随机范围偏移完成后，`FighterCombat2D` 使用最终攻击范围进行目标保持、距离判定和 Gizmo 绘制。
- 射速：`FighterCombat2D.UpdateShooting` 同时推进默认发射模式与装备效果控制器。

## 7. 飞机与子弹生命周期

生命周期倍率只影响新创建的对象，已存在的飞机和子弹不会因为面板应用新配置而重算剩余寿命。

`LifetimeAndScreenBounds2D` 在 `Awake` 保存 `ConfiguredLifetime`，作为预制体/配置基准寿命；之后通过 `SetLifetime` 写入实际寿命不会污染该基准，因此重复初始化不会叠乘倍率。

- `Fighter2D.Initialize`：用 `ConfiguredLifetime × 飞机存活时间倍率` 设置新飞机寿命。
- `Projectile2D.Initialize`：速度乘以子弹速度倍率。
- `Projectile2D.Initialize`：显式发射上下文寿命优先；没有显式寿命时使用弹体 `ConfiguredLifetime`，之后乘以子弹存活时间倍率。

因此正式飞机子弹、装备子弹与 Test Shooter 中通过 `Projectile2D` 创建的子弹，都会使用相同的子弹速度/寿命规则；激光、范围伤害和纯视觉特效不受影响。

相关文件：

```text

Assets/Scripts/Battle/Fighter/Fighter2D.cs
Assets/Scripts/Battle/Combat/Projectile2D.cs
```

## 9. 后续扩展注意事项

- 新增风格参数时必须同时更新：`StyleTendencyMultipliers`、`StyleTendencyDebugSettings`、`StyleTendencyDebugRuntime`、`StyleTendencyDebugWindow` 的草稿相等比较和校验、两个预置资产以及测试。
- 调整冷却方式之外的参数，不应触发 `CooldownItemTypeChanged`，否则会意外重置战斗中冷却。
- 新增飞行子弹实现时，优先接入 `Projectile2D.Initialize`，以自动获得全局子弹速度和寿命倍率。
- 对寿命做运行时二次设置时，应明确使用 `ConfiguredLifetime` 还是当前 `Lifetime`，避免重复乘上风格倍率。
