# 敌人背包行为说明

## 概览

`SampleScene` 中的敌人使用独立的 `EnemyBackpackSystem`。敌人不复制玩家背包，而是从共用的五套 `DeckPreset` 中随机选取一套，并在敌人自己的 7×4 背包上自动摆放和操作。

## 初始预设与摆放

- 首次进入准备阶段时，敌人从 `DeckPreset_01` 至 `DeckPreset_05` 的预设池随机选择一套。
- 预设中的非空物品会尝试完整放入背包。布局器会生成多份合法候选布局，优先选择：
  1. 单件装备相邻到更多不同飞机的布局；
  2. 装备与飞机相邻关系更多的布局；
  3. 整体更靠近背包中心的布局。
- 敌人不会沿玩家使用的从左到右扫描规则水平铺开。
- 后续准备阶段保留上轮的敌人物品和布局，不会重新随机预设或重置初始摆放。

## 隐藏商店

- 敌人有一个不显示 UI 的三格商店。
- 商店物品从当前敌人预设中的非空物品随机抽取，允许重复。
- 每次进入准备阶段会刷新三件库存。
- 敌人添加物品会从该库存取走一件；库存不足三件时，敌人有 **80%** 概率优先 Roll，将库存重新刷新为三件。
- Roll 是一次敌人操作，因此会消耗本准备阶段的操作额度。

## 自动操作

- 默认每隔 **1 秒**尝试一次操作；一次完整动效结束后才开始计算下一次间隔。
- 每个准备阶段默认最多完成 **4 次成功的普通操作**。失败的选择不会扣次数。
- 敌人操作串行播放移动、加入、移除、替换及合成的视觉反馈，避免多个操作动画重叠。
- 玩家每次成功改变背包模型（移动、添加、移除、替换、合成升级）时，敌人会额外排队执行一次操作；此操作不消耗敌人的四次额度。
- 进入战斗阶段时，未开始的敌人操作会取消，敌人不再继续修改背包。

### 决策优先级

只要商店中存在至少一件可合法放入背包的物品：

- 敌人有 **85%** 概率直接添加商店物品。
- 其余情况下主要会移动物品、Roll 商店或替换物品。

“能否继续添加”按实际物品形状和当前占用格逐项判断；不是单纯按空格数量判断。

当商店内没有任何物品能够继续放入时，敌人才会考虑空间整理操作：

- **合成**：只合成两个相同的 1 级物品，权重较低。
- **移除**：只有背包所有格子都被占满时才允许，且权重低于移动、Roll 和替换。
- **替换**：先验证新物品能否占用被替换物品的位置；验证成功才移除旧物品并加入新物品，避免失败时丢失旧物品。

敌人不追求绝对最优解：移动和替换可能是低收益操作。

## 调试面板

进入 Play Mode 后，在 **Tools > Debug > 程序测试面板 > 敌人背包** 可使用：

- 查看当前预设、剩余操作次数、操作状态和隐藏商店库存；
- 选择指定预设或随机选取预设；两者都会刷新敌人的操作次数；
- 按当前预设随机摆放初始物品；
- 手动执行一次敌人背包操作；
- 手动刷新操作次数；
- 调整操作间隔和最大操作次数。

预设发生变化时，操作额度会恢复为当前的最大次数，并重新开始自动操作计时。
