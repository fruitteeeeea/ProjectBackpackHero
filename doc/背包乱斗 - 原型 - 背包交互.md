# 背包乱斗 - 背包交互需求

## 1. 本阶段目标

本阶段只实现 Unity UI 背包交互与调试工具，不实现战斗、金币、回合、装备属性、购买价格、随机刷新权重和存档。

背包界面不再由运行时代码创建。背包、背包格子、商店槽位、垃圾桶和物品都必须制作成 Prefab，并在独立调试场景中通过 Inspector 连接。商店刷新时允许从物品 Prefab 实例化三个商品，但不允许在运行时创建整套背包 UI 结构。

## 2. 最终界面

```text
BackpackDebugCanvas
├── PlayerBackpack
│   ├── BackpackBackground
│   ├── GridLayer
│   │   └── 28 个 BackpackSlotPrefab
│   └── ItemLayer
├── ShopPanel
│   ├── ShopSlot_0
│   ├── ShopSlot_1
│   └── ShopSlot_2
├── TrashZone
└── DragLayer
```

- 上方是玩家 7x4 背包，直接使用背包 Prefab 在场景中摆放。
- 下方是商店，包含三个商品槽位。
- 商店右侧是垃圾桶。背包物品或商店物品拖到垃圾桶后删除。
- `DragLayer` 位于最上层，只用于拖拽中的显示。

## 3. 预制体与美术资源

必须建立以下可视化预制体：

1. `BackpackSlotPrefab`
2. `PlayerBackpackPrefab`
3. `ShopSlotPrefab`
4. `ShopPanelPrefab`
5. `TrashZonePrefab`
6. 七个具体方向的物品 Prefab
7. 可选的完整 `BackpackDebugCanvasPrefab`

美术规则：

- 格子和背包外观使用 `Assets/Art/Images/Backpack/` 中的素材。
- 格子当前使用 `Assets/Art/Images/Backpack/SlotPanel (1).png`。
- 物品图片使用 `Assets/Art/Images/Item/` 中的素材，不再显示纯色方块和测试文字。
- Image 的 Sprite 必须与 `ItemShapeData.Icon` 保持一致。

## 4. 装备类型

只保留三类装备，共七个具体方向变体：

| 类别 | 变体 | 素材 |
| --- | --- | --- |
| 正方形 | 1×1 | `Item_Block/item_1x1.png` |
| 一字型 | 1×2 | `Item_Bar/item_1x2.png` |
| 一字型 | 2×1 | `Item_Bar/item_2x1.png` |
| L 型 | 4 个方向 | `Item_L/item_L_rot000.png` 等四张素材 |

所有形状继续使用 `shapeOffsets`，不使用 width/height 写死占用逻辑。

```text
1x1:
(0,0)

1x2:
(0,0) (0,1)

2x1:
(0,0) (1,0)

L 型四向（2x2 范围内缺一角）:
A: (0,0) (0,1) (1,1)
B: (0,0) (1,0) (0,1)
C: (0,0) (1,0) (1,1)
D: (1,0) (0,1) (1,1)
```

`item_L_rot360.png` 作为第四个方向素材使用。制作 `ItemShapeData` 时必须根据图片中的实际缺角方向匹配上述四组 offsets，不只根据文件名猜测。

## 5. 数据和坐标规则

- 背包是 7列×4行，共28个格子。
- 左上角是 `(0,0)`，右下角是 `(6,3)`。
- x 向右增加，取值范围为 `0～6`。
- y 向下增加，取值范围为 `0～3`。
- `BackpackController` 仍是背包占用数据的唯一可信来源。
- `ItemView` 只负责显示、输入和动效，不直接修改占用数组。
- 物品不得永久挂在某一个 Slot 下，放置后属于 `ItemLayer`。
- 预览、`CanPlace`、最终放置必须使用同一个 `anchorCell`。

```text
occupiedCell = anchorCell + shapeOffset
anchorCell = pointerCell - grabCellOffset
```

`CanPlace(item, anchorCell, ignoreItem)` 必须继续检查越界、与其他物品重叠，并在移动背包内物品时忽略物品自己的旧占用格。

## 6. 拖拽和反馈

- 开始拖拽时保留 `dragVisualOffset`，图片不得跳位。
- 根据按下的具体占用格计算 `grabCellOffset`。
- 合法预览显示黄色，非法预览显示红色。
- 部分越界时，背包内可见部分仍显示红色。
- 商店物品合法放入背包后，对应商店槽位变空。
- 背包物品可再次移动；非法放置回到原位。
- 物品拖到垃圾桶时优先执行删除，无需检查 `CanPlace`。

DOTween 参数现阶段保持不变：

- Hover：`1.0 -> 1.08`。
- BeginDrag：缩放到 `1.05`，alpha 降到 `0.86`。
- 放置成功：`DOPunchScale` 和 UI 扩散效果。
- 放置失败：回到原位并 `DOShakePosition`。
- 新 Tween 开始前 Kill 同类旧 Tween。

## 7. 商店规则

- 商店有三个固定槽位。
- 刷新时先清理旧商品，然后为每个槽位从七个具体变体中独立随机抽取一个。
- 允许三个槽位出现重复物品。
- 刷新只实例化已制作的物品 Prefab，不动态创建物品 UI 结构或 `ItemShapeData`。

## 8. 默认背包

“恢复默认”重建一个固定示例布局，用于验证不同形状：

- 1×1：锚点 `(0,0)`。
- 1×2：锚点 `(1,0)`。
- L 型：锚点 `(2,1)`，选择不越界且不与前两件重叠的方向。

恢复时必须清理当前背包数据和物品视图，再从预制体重建默认物品，不能只重置 Transform。

## 9. 背包调试面板

参考 `Assets/AGENT/Unity - 调试面板创建.md`，使用 Unity `EditorWindow` + IMGUI，并建立不引用 `UnityEditor` 的 Runtime 调试桥接。

面板现阶段只包含：

1. `恢复默认`按钮。
2. `刷新商店物品`按钮。
3. `显示当前物品信息`按钮。
4. 当前物品信息区域。
5. 当前背包物品表格，物品名称垂直排列。

“当前物品”是最近点击的商店或背包物品。点击显示按钮后，面板显示物品名称、具体形状、来源（商店/背包）；若已在背包中，同时显示 `anchorCell`。没有选中项时必须显示提示，不报错。

调试窗口在 Play Mode 且调试场景 Runtime 存在时自动打开，Runtime 销毁或退出 Play Mode 时自动关闭，并保留 `Tools` 菜单手动入口。

## 10. 职责边界

- `ItemShapeData`：编辑器内创建的静态资源，保存名称、Sprite 和 offsets。
- `ItemInstance`：保存实例 ID、数据和锚点。
- `BackpackController`：唯一占用数据源。
- `BackpackGridView`：保存 Inspector 连接的网格和 Slot，负责坐标换算与预览。
- `BackpackSlotView`：显示美术格子和预览颜色。
- `ItemView`：显示 Sprite、处理点击、拖拽与动效。
- 场景 Runtime 控制器：保存所有序列化引用，恢复默认、刷新商店、实例化物品 Prefab，并对调试桥接提供稳定接口。
- EditorWindow：只通过 Runtime 桥接读写，不直接操作背包内部数组。

`BackpackPrototypeBootstrap` 及其运行时创建 Canvas、面板、格子、按钮、文字和测试形状的职责已移除。`PlacementEffectPlayer` 和现有 DOTween 反馈保留。

## 11. 验收标准

1. 不运行游戏时，在新调试场景中就能看到背包、28 个格子、三个商店槽位和垃圾桶。
2. 所有背包、格子、商店槽、垃圾桶和物品都可从 Prefab 进入 Prefab Mode 单独调整。
3. 七个物品变体的图片、显示尺寸和实际占用格一致。
4. 刷新商店后三个槽位各有一个随机物品，允许重复。
5. 商店物品能放入背包，背包物品能移动和删除。
6. 重叠、越界和忽略自身占用的规则保持正确。
7. 四向 L 型的高亮、最终显示和占用数据完全一致。
8. 点击物品后调试面板能显示当前物品信息。
9. 调试面板的背包表格与实际背包数据同步。
10. “恢复默认”每次都得到相同的固定布局。
11. Hover、拖拽、成功放置和失败放置动效保持现有效果。
