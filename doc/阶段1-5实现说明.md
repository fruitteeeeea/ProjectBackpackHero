# 背包交互 - 旧原型基线与重构结果

## 1. 文档用途

本文档记录预制体化改造前复用的背包数据和交互能力，以及已移除的旧运行时调试实现。

本文档不再把 `SampleScene` 或 `BackpackPrototypeBootstrap` 视为背包交互的最终入口。新入口将是独立的背包调试场景和场景中直接摆放的 Prefab。

## 2. 继续保留的数据层

`BackpackController` 继续作为背包数据的唯一可信来源，保留以下能力：

- 目标场景使用 7 列×4 行占用数组，共 28 格。
- `BackpackController` 仍通过构造参数接收宽高，数据算法不写死 7×4。
- `GetOccupiedCells`。
- `CanPlace(item, anchorCell, ignoreItem)`。
- `PlaceItem`。
- `MoveItem`。
- `RemoveItem`。
- 越界、重叠、移动时忽略自身占用。

`ItemShapeData` 继续使用 `shapeOffsets` 描述形状。七个正式形状已在 `Assets/Data/Backpack/ItemShapes/` 中创建成 ScriptableObject 资源，运行时不再创建测试形状。`InitializeForRuntime` 仅保留给 EditMode 单元测试构造临时数据。

## 3. 继续保留的交互层

`BackpackGridView`、`BackpackSlotView`、`ItemView` 和 `PlacementEffectPlayer` 的核心逻辑保留：

- 屏幕坐标转背包坐标。
- `anchorCell = pointerCell - grabCellOffset`。
- 黄色/红色放置预览。
- `dragVisualOffset` 防止拖拽跳位。
- 商店到背包的放置。
- 背包内再次移动。
- 垃圾桶删除。
- Hover、Punch、Shake 和 UI 扩散效果。

重构后这些组件通过 Prefab 和 Inspector 获取引用，交互算法和现有 DOTween 参数保持不变。

## 4. 新的装备范围

删除旧的 1×3 和 2×2 测试装备定义，只保留：

- 1×1 正方形。
- 1×2 竖向一字型。
- 2×1 横向一字型。
- 四个方向的三格 L 型。

七个具体变体均需要独立 `ItemShapeData` 资源和物品 Prefab。

## 5. 已移除的旧实现

`BackpackPrototypeBootstrap` 文件、meta、代码引用和场景/Prefab 引用已清理。被移除的旧职责包括：

- 运行时创建 Canvas、Root、商店和背包面板。
- 运行时创建整套格子（旧原型固定为 16 格）。
- 运行时创建按钮、文字、垃圾桶和拖拽层。
- 运行时创建 1×1、1×3、2×2 测试形状。
- 用纯色 Image 和 Text 组装物品视图。
- 三个形状生成按钮和单一商店物品的逻辑。

改造后，以上对象是场景实例或 Prefab 实例。只有“刷新商店”、“恢复默认背包”和拖拽放置过程会在 Play Mode 中实例化已存在的物品 Prefab。

## 6. 新的美术资源基线

- 物品图片：`Assets/Art/Images/Item/`。
- 背包和格子图片：`Assets/Art/Images/Backpack/`。
- 格子默认图片：`SlotPanel (1).png`。

纯色方块只允许用于必要的高亮叠层，不得继续作为背包或物品主视觉。

## 7. 测试基线

现有 `BackpackControllerTests` 已保留数据层边界、重叠、忽略自身和删除测试，并将与 1×3、2×2 绑定的用例替换为：

- 1×2 竖向边界。
- 2×1 横向边界。
- 四向 L 型边界和占用。
- 7×4 最后一格与右/下边界。
- `grabCellOffset` 的锚点计算。
- 越界预览保留背包内可见格。

Unity Test Runner 的批处理命令可继续使用，但当前环境曾出现 Unity Licensing Client 连接失败，自动化结果必须以实际生成的 Test Results 为准。
