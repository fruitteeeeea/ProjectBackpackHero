# 背包交互 - 预制体化改造说明

## 1. 改造状态

2026-07-22，预制体化的主体实现已完成。工程已包含独立调试场景、7×4 玩家背包、三槽商店、垃圾桶、七个物品变体、Runtime 调试桥接和 EditorWindow。

本文档中“已完成”表示相关资源和代码已存在并完成引用配置；Unity Test Runner 和完整 Play Mode 手工验收结果仍需单独记录。

## 2. 阶段 6：编辑器资源（已完成）

- 已建立七个 `ItemShapeData` 资源：1×1、1×2、2×1 和四向 L。
- 资源位于 `Assets/Data/Backpack/ItemShapes/`。
- 物品使用 `Assets/Art/Images/Item/` 中的 Sprite。
- 背包格子使用 `Assets/Art/Images/Backpack/SlotPanel (1).png`。
- 四向 L 使用 2×2 范围内缺一角的三格 offsets。

## 3. 阶段 7：预制体和调试场景（已完成）

已建立 `Assets/Scenes/BackpackDebugScene.unity`，不再使用 `SampleScene` 作为背包交互开发入口。

已建立：

- `BackpackDebugUI.prefab`。
- `PlayerBackpack.prefab`，包含 28 个格子、`GridLayer` 和 `ItemLayer`。
- `BackpackSlot.prefab`。
- `ShopPanel.prefab` 和 `ShopSlot.prefab`。
- `TrashZone.prefab`。
- 1×1、1×2、2×1 和四向 L 的七个物品 Prefab。
- 全屏 `DragLayer`。

背包尺寸为 7 列×4 行，坐标范围为 `(0,0)` 到 `(6,3)`。`BackpackGridView` 通过 Inspector 保存 `columns = 7`、`rows = 4`、格子尺寸、间距和 28 个 Slot 引用。

## 4. 阶段 8：场景 Runtime 与商店（已完成）

`BackpackDebugRuntime` 只负责运行时数据和已存在 Prefab 的实例化，不创建 Canvas、背包、格子、商店面板或垃圾桶。

场景中已序列化连接：

- `BackpackGridView`、`ItemLayer`、`DragLayer` 和 `TrashZone`。
- 三个商店槽位。
- 七组 `ItemShapeData + ItemView Prefab`。
- 固定默认背包布局。

对外接口：

```text
RestoreDefaultBackpack()
RefreshShop()
SelectedItem
GetBackpackItems()
```

`RefreshShop()` 清理旧商品后，为三个槽位独立随机抽取七个变体，允许重复。`RestoreDefaultBackpack()` 恢复固定的 1×1、1×2 和 L 型示例布局。

## 5. 阶段 9：背包调试面板（已完成）

`Assets/Editor/BackpackDebug/` 中已建立：

- `BackpackDebugWindow.cs`。
- `BackpackDebugWindowLifecycle.cs`。

窗口通过 `BackpackDebugRuntime.Instance` 访问 Runtime，不直接修改背包内部数据。已实现：

1. `恢复默认`。
2. `刷新商店物品`。
3. `显示当前物品信息`。
4. 最近点击/开始拖拽物品的名称、形状、来源和锚点。
5. 背包物品名称的垂直列表。
6. Play Mode Runtime 可用时自动打开，退出或 Runtime 消失时自动关闭。
7. `Tools/Backpack/Backpack Debug` 手动菜单入口。
